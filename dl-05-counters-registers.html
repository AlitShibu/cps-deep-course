Counters & Registers

Chapter 4 gave you a single bit of memory. This chapter chains many flip-flops together to build the two workhorses of every digital system: registers, which hold a multi-bit value steady, and counters, which advance through a sequence automatically on every clock tick — literally the mechanism behind every timer peripheral you'll touch in your Microcontrollers roadmap topic.

Section 5.1

Registers — a multi-bit value held steady

A single D flip-flop (Chapter 4) stores exactly one bit. A register is simply several D flip-flops, sharing one clock signal, each holding one bit of a wider value — an 8-bit register is 8 flip-flops side by side, together holding one 8-bit number.

A register: several flip-flops sharing one clock, together storing one multi-bit value.
Why sharing one clock line matters

If each flip-flop in a register updated on its own separate timing, the register's 8 bits could briefly represent 8 different "moments" of the value rather than one consistent number — reading it mid-update could return a meaningless mix of old and new bits. A shared clock guarantees all 8 bits change at exactly the same instant (Chapter 4's edge-triggering, now applied across many flip-flops at once), so the register always holds one coherent, well-defined value.

Parallel load — writing a new value into a register

A register typically has a "load enable" control alongside its data inputs: when load is active, the next clock edge captures new D inputs into every flip-flop simultaneously; when inactive, each flip-flop simply feeds its own current output back into its own input, holding steady (a direct application of Chapter 4's SR latch "hold" behavior, generalized). This is exactly the mechanism behind a CPU's registers — the small, extremely fast storage locations a processor uses for values actively being computed with.

Section 5.2

Counters — advancing automatically, every clock tick

The toggle (T) flip-flop — the building block of counting

A T flip-flop flips its own output on every clock edge (0→1, then 1→0, then 0→1, forever) — built from a D flip-flop by simply wiring its own inverted output (Q') back into its D input, so it always "requests" the opposite of its current state at the next edge.

Chaining T flip-flops into a binary counter

Connect several T flip-flops so each one's output clocks the next flip-flop in the chain, and you get exactly the binary counting sequence from Chapter 1: 000, 001, 010, 011, 100... — each flip-flop represents one bit, toggling at half the rate of the one before it, precisely matching how each binary place value is worth double the one to its right.

Bit 0 toggles every clock edge; Bit 1 only toggles when Bit 0 goes high-to-low — exactly reproducing binary counting, one flip-flop per bit.
Ripple counters vs. synchronous counters — a real design tradeoff

The chain described above is a ripple counter — simple to build, but each bit's change depends on the previous bit's change finishing first, so a change can take slightly longer to "ripple" through all the bits for large counters, introducing brief, incorrect intermediate values. A synchronous counter instead drives every flip-flop from the exact same clock signal directly (using additional combinational logic to compute each bit's next value), eliminating the ripple delay at the cost of more gates. This is a genuine engineering tradeoff between simplicity and speed/correctness at higher clock frequencies — synchronous designs dominate in modern high-speed systems.

Where this shows up directly in your Microcontrollers topic

Every microcontroller's timer peripheral is, at its core, exactly this kind of counter — a register that automatically increments on every clock tick (or every Nth tick), which your embedded C code reads or configures to trigger interrupts at precise intervals. When you set up a timer to fire every 1ms in embedded C, you are configuring the parameters of a hardware counter built from exactly the flip-flop chains this section describes.

Section 5.3

Shift registers — moving data sideways

Instead of each flip-flop holding its own independent bit fed by external logic, a shift register chains flip-flops so each one's D input comes from the previous flip-flop's Q output. On every clock edge, every bit moves one position down the chain — a new bit enters at one end, and the bit that was at the far end falls off.

Why this matters — serial-to-parallel conversion

Recall C Chapter 5's Serial Protocols topic: UART, I2C, and SPI all send data one bit at a time over a wire. A shift register is exactly the hardware mechanism that collects those individual incoming bits, one clock edge at a time, and makes the complete assembled byte available all at once, in parallel, once enough bits have arrived — this is literally happening inside every UART/SPI peripheral's receive hardware, converting a serial bit stream into the parallel byte your C code actually reads. The reverse (parallel-to-serial) works identically, in the opposite direction, and is exactly how those same peripherals transmit a byte one bit at a time.

Section 5.4

Worked problem — designing a mod-6 counter

Problem

Design a counter that counts 0, 1, 2, 3, 4, 5, then wraps back to 0 (a "mod-6" counter) — useful, for instance, to cycle through 6 LEDs in sequence.

3 bits are needed (2^2=4 is too few to reach 5; 2^3=8 is enough, with values 6,7 unused)

Binary sequence needed: 000, 001, 010, 011, 100, 101, then back to 000

A plain 3-bit binary counter (Section 5.2) naturally counts 000 through 111 (0-7) --
it would need to be forced to reset early, at count 6 (110), instead of running to 7.

Design approach: add combinational logic (Chapter 3) that detects when the count
reaches 110 (6) and forces an immediate reset back to 000, rather than letting
the counter continue counting naturally to 111.

Detection logic: Reset = Q2 · Q1 · Q0'   (true exactly when the count is 110)

Why this works: the moment the counter would reach binary 110 (which is 6 — one past the desired maximum of 5), the detection logic immediately drives a reset signal, forcing all flip-flops back to 000 before that unwanted value can ever appear as a stable output. This exact combine-a-counter-with-detection-logic pattern is the general technique for building a counter of any desired length, not just powers of 2 — directly combining this chapter's flip-flop chains with Chapter 3's combinational logic design.

Wrap-up

Recap

  1. A register is several flip-flops sharing one clock, together holding one multi-bit value coherently — the shared clock guarantees every bit updates simultaneously.
  2. A T flip-flop toggles every clock edge; chaining T flip-flops, each driven by the previous one's output, builds a binary counter that naturally reproduces Chapter 1's counting sequence.
  3. Ripple counters are simple but suffer propagation delay through the chain; synchronous counters drive every flip-flop directly for speed, at the cost of more logic — a real, common engineering tradeoff.
  4. Microcontroller timer peripherals are, at their core, exactly these counter circuits — configuring a timer in embedded C means configuring hardware built from flip-flop chains like these.
  5. A shift register moves bits one position per clock edge — the direct hardware mechanism behind serial-to-parallel and parallel-to-serial conversion in UART/SPI peripherals (C's Serial Protocols topic).
  6. A counter of any desired length (not just a power of 2) can be built by combining a natural binary counter with detection logic that forces an early reset — Chapter 3's combinational design directly applied to Chapter 4's sequential building blocks.
Check yourself

Quick check

Question 1

Why must all flip-flops in a register share the exact same clock signal?

If different flip-flops updated at slightly different times, the register could briefly hold a meaningless mix of old and new bits -- reading it during that window would return an inconsistent, undefined value. A shared clock guarantees every bit changes at exactly the same instant, keeping the register's value always coherent.
Question 2

What real hardware inside a microcontroller is directly built from the flip-flop counter chains in this chapter?

Timer peripherals -- a hardware timer that increments on every clock tick (or every Nth tick) to trigger interrupts at precise intervals is, at its core, exactly this kind of flip-flop-based counter circuit.
Question 3

What's the general technique for building a counter that counts to a value that isn't a power of 2 (like counting 0-5 instead of 0-7)?

Build a normal binary counter of sufficient width, then add combinational logic that detects the moment the count reaches one past the desired maximum value, and uses that detection to force an immediate reset back to zero -- combining Chapter 3's combinational design with this chapter's counter circuits.

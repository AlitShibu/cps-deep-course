Systems of Linear Equations

Almost every engineering problem that reduces to "solve for these unknowns" eventually becomes a system of linear equations — sensor calibration, circuit analysis, and (later, in Control Systems II) finding a state-space controller's gains. This chapter covers what a system of equations really represents, and the systematic method for solving it: Gaussian elimination.

Section 3.1

What a system of linear equations represents

A system of linear equations is a set of equations, each linear (no squared terms, no products of unknowns), that must all be true simultaneously. A small example:

2x + y = 8
 x - y = 1

"Solving" this means finding the specific values of x and y that satisfy both equations at once.

The geometric picture

Each linear equation in two unknowns describes a straight line (in three unknowns, a flat plane; in more, a "hyperplane" — the same idea, just impossible to draw). Solving a system means finding where all those lines (or planes) intersect.

Two lines meeting at exactly one point — the unique solution to the system.

Rewriting as a matrix equation: Ax = b

This is where Chapter 2's matrix-vector multiplication becomes directly useful. Separate the coefficients of the unknowns from the unknowns themselves and from the right-hand-side constants:

2x + y = 8         [ 2   1 ] [x]   [8]
 x - y = 1    →     [ 1  -1 ] [y] = [1]

                        A       x  =  b

Reading this: A holds every coefficient, x is the (unknown) vector we're solving for, and b is the vector of right-hand-side values. "Solve the system" and "find the vector x that A transforms into b" are exactly the same question — this is precisely why Chapter 2's transformation-machine mental model matters here: solving Ax = b is asking "which input vector does the A-machine turn into output b?"

Section 3.2

Gaussian elimination — the systematic method

Guessing solutions to a 2-equation system by inspection is fine, but real engineering systems can have dozens or thousands of equations. Gaussian elimination is a completely mechanical procedure that solves any system, however large, by strategically adding multiples of one equation to another until each equation involves one fewer unknown than the last — a staircase pattern called row echelon form.

The core legal moves ("row operations")

You're always allowed exactly three operations on a system's rows without changing its solution:

  • Swap two rows (equations can be listed in any order).
  • Scale a row by any non-zero number (multiplying both sides of an equation by the same number doesn't change what makes it true).
  • Add a multiple of one row to another (this is the workhorse move — it's how you eliminate a variable from an equation).

Full worked example, step by step

2x + y = 8
 x - y = 1

Write as an augmented matrix — the coefficient matrix with the b-vector tacked on as an extra column:

[ 2   1 | 8 ]
[ 1  -1 | 1 ]

Step 1: Eliminate x from row 2. Subtract half of row 1 from row 2 (chosen so the x-coefficient in row 2 becomes zero: row2 − 0.5×row1):

row2_new = [1,-1|1] - 0.5*[2,1|8] = [1-1, -1-0.5, 1-4] = [0, -1.5, -3]

[ 2    1  |  8  ]
[ 0  -1.5 | -3  ]

Step 2 (back substitution): Row 2 now says -1.5y = -3, so y = 2. Substitute back into row 1: 2x + 2 = 8 → 2x = 6 → x = 3.

Solution: x = 3, y = 2 — matching the intersection point shown in the diagram from Section 3.1.

Gaussian elimination: eliminate variables systematically, then solve backward from the simplest equation.

A larger worked example — 3 equations, 3 unknowns

This scales exactly the same way, just with more steps:

 x + y + z = 6
2x + y - z = 1
 x - y + z = 2
Augmented matrix:
[ 1   1   1 | 6 ]
[ 2   1  -1 | 1 ]
[ 1  -1   1 | 2 ]

Step 1: eliminate x from rows 2,3 using row 1
  row2 -= 2*row1:  [0, -1, -3 | -11]
  row3 -=   row1:  [0, -2,  0 |  -4]

[ 1   1   1 |  6  ]
[ 0  -1  -3 | -11 ]
[ 0  -2   0 |  -4 ]

Step 2: eliminate y from row 3 using row 2
  row3 -= 2*row2:  [0, 0, 6 | 18]

[ 1   1   1 |  6 ]
[ 0  -1  -3 | -11]
[ 0   0   6 |  18]

Back-substitute: row3 → 6z=18 → z=3
row2 → -y -3(3) = -11 → -y = -2 → y=2
row1 → x + 2 + 3 = 6 → x = 1

Solution: x=1, y=2, z=3

In NumPy — you'll almost never do this by hand in practice

import numpy as np

A = np.array([[1, 1, 1],
              [2, 1, -1],
              [1, -1, 1]])
b = np.array([6, 1, 2])

x = np.linalg.solve(A, b)
print(x)   # [1. 2. 3.]
Why learn to do it by hand at all, then?

Because understanding the mechanical process is what makes the failure modes in Section 3.3 make sense — when a system has no solution or infinitely many, it shows up as a specific, recognizable pattern during elimination (a row that reduces to something like 0 = 5, an impossible statement, or a row that reduces to 0 = 0, a statement that's true but useless). If you've never done elimination by hand, those patterns look like arbitrary edge cases in np.linalg.solve's error messages instead of the direct, meaningful signals they actually are.

Section 3.3

The three possible outcomes

Every system of linear equations falls into exactly one of three categories. Recognizing which one you're in — both geometrically and from the algebra — is as important as being able to execute elimination.

Two lines: cross once (unique), never cross (none), or are the same line (infinite).
OutcomeGeometric pictureSignal during elimination
Unique solutionLines/planes cross at exactly one pointEvery variable gets pinned down to one value by back-substitution.
No solutionLines/planes are parallel, never meetElimination produces a row like 0 = 5 — a false, impossible statement.
Infinite solutionsLines/planes overlap entirelyElimination produces a row like 0 = 0 — true but uninformative, meaning one equation was redundant.
Worked example — the "no solution" case

Problem: Solve x + y = 4 and 2x + 2y = 10.

[ 1  1 | 4 ]
[ 2  2 | 10]

row2 -= 2*row1:  [0, 0 | 10 - 8] = [0, 0 | 2]

[ 1  1 | 4 ]
[ 0  0 | 2 ]

The second row reads 0x + 0y = 2, i.e. 0 = 2 — false, no matter what x and y are. No solution exists. Geometrically, the two original equations describe parallel lines (the second is "the first, doubled" on the left side, but not on the right — an inconsistency).

Why an engineer needs to recognize this, not just compute it

If you set up a system modeling a real physical situation — say, solving for unknown currents in a circuit, or unknown forces on a structure — and elimination produces a 0 = 5-style contradiction, that's not a math error to "fix" by tweaking numbers. It's telling you your model is wrong: you've written down equations that can't simultaneously be true, which usually means you've mis-modeled a physical constraint or made a measurement error somewhere upstream. The math is doing its job by refusing to lie to you with a fake answer.

Detecting these cases in NumPy

import numpy as np
A = np.array([[1,1],[2,2]])
b = np.array([4,10])
try:
    x = np.linalg.solve(A, b)
except np.linalg.LinAlgError as e:
    print("No unique solution:", e)
    # Real code would inspect further (e.g. via least-squares or rank checks,
    # covered properly in Chapter 5) to tell "no solution" apart from "infinite solutions"
Wrap-up

Recap

  1. A system of linear equations describes intersecting lines/planes; solving it means finding the point(s) where all of them agree simultaneously.
  2. Any system can be rewritten as Ax = b, turning "solve the system" into "find which vector the matrix A maps to b" — directly using Chapter 2's transformation view of matrices.
  3. Gaussian elimination uses three legal row operations (swap, scale, add-a-multiple) to reduce a system to a staircase pattern, then solves it via back-substitution, from the simplest equation up.
  4. Every system has exactly one of three outcomes: a unique solution, no solution (elimination yields a contradiction like 0=5), or infinite solutions (elimination yields a redundant 0=0).
  5. In practice, np.linalg.solve does elimination for you — but recognizing the three outcomes by hand is what lets you correctly interpret what a solver is telling you when something other than a clean unique answer comes back.

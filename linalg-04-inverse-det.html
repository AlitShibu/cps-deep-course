Matrix Inverse & Determinants

Chapter 3 solved Ax = b mechanically, one system at a time. This chapter asks a more general question: is there a single matrix that undoes A's transformation entirely — and how do you know, before doing any work, whether that's even possible? Determinants answer the second question; inverses answer the first.

Chapter 4 of 9Python / NumPyBuilds on Chapters 2-3
Section 4.1

What a matrix inverse is

Recall Chapter 2's core idea: a matrix is a machine that transforms vectors. The inverse of matrix A, written A⁻¹, is the machine that exactly undoes A's transformation — apply A, then apply A⁻¹, and you're back where you started:

A⁻¹(Av) = v      for every vector v
A⁻¹A = AA⁻¹ = I   (the identity matrix from Chapter 2)
Applying A then A⁻¹ (in either order) always returns you to the original vector — that's the entire definition.

Once you have A⁻¹, solving Ax = b (Chapter 3) becomes a single multiplication instead of a full elimination process: x = A⁻¹b. This looks like it makes Chapter 3 obsolete — Section 4.4 explains why, in real code, it's actually the other way around.

Not every matrix has an inverse

This is the crucial catch. A matrix that squashes two different input vectors onto the exact same output vector has thrown away information — and no machine can un-throw-away information, so no inverse can exist. A matrix with an inverse is called invertible (or non-singular); one without is singular.

The geometric signature of a non-invertible matrix

Picture a matrix that squashes all of 2D space onto a single line (this actually happens — e.g. [[1,1],[2,2]] sends every input to a multiple of (1,2)). Every point that used to lie off that line has been permanently collapsed onto it, indistinguishable from every other point that landed at the same spot. There's no way to "unsquash" a line back into a full 2D plane — the information about which of the many original points you started from is simply gone. This geometric collapse — losing a dimension — is exactly what a zero determinant (next section) detects.

Section 4.2

The determinant — detecting invertibility before you compute anything

The geometric meaning: area/volume scaling factor

The determinant of a matrix, written det(A) or |A|, tells you the factor by which the matrix scales area (in 2D) or volume (in 3D and beyond). A matrix with det(A) = 3 triples the area of any shape it transforms. A matrix with det(A) = 1 preserves area exactly (rotation matrices always have determinant 1 — rotating never stretches or squashes anything). A negative determinant means the transformation also flips orientation (like a reflection) in addition to scaling.

The determinant is exactly the factor by which a matrix scales area — start with area 1, end with area |det(A)|.

The crucial connection: zero determinant means non-invertible

The single fact this whole section builds toward

A matrix is invertible if and only if its determinant is non-zero. A determinant of zero means the matrix squashes area (or volume) down to zero — collapsing 2D space onto a line, or 3D space onto a plane or line — exactly the information-destroying collapse described in Section 4.1. Before ever attempting to find an inverse, checking the determinant tells you instantly whether the attempt is even possible.

Computing a 2×2 determinant

A = [ a  b ]
    [ c  d ]

det(A) = ad - bc

Example: A = [[3,1],[2,4]] → det(A) = 3×4 - 1×2 = 12 - 2 = 10 — non-zero, so A is invertible.

Computing a 3×3 determinant (cofactor expansion)

Expand along the first row, using each entry's cofactor — the determinant of the smaller matrix left after deleting that entry's row and column, with alternating signs:

A = [ a  b  c ]
    [ d  e  f ]
    [ g  h  i ]

det(A) = a*(ei - fh) - b*(di - fg) + c*(dh - eg)
Worked problem

Problem: Compute the determinant of A = [[2,0,1],[1,3,0],[0,1,2]] and determine if it's invertible.

det(A) = 2*(3*2 - 0*1) - 0*(1*2 - 0*0) + 1*(1*1 - 3*0)
       = 2*(6-0) - 0*(2-0) + 1*(1-0)
       = 2*6 - 0 + 1*1
       = 12 + 1 = 13

det(A) = 13 ≠ 0, so A is invertible.

In NumPy

import numpy as np
A = np.array([[2,0,1],[1,3,0],[0,1,2]])
print(np.linalg.det(A))   # 13.0 (up to tiny floating-point noise)
Section 4.3

Computing an inverse

The 2×2 shortcut formula

For a 2×2 matrix, there's a direct formula worth memorizing — swap the diagonal entries, negate the off-diagonal entries, and divide everything by the determinant:

A = [ a  b ]         A⁻¹ = (1/det(A)) * [  d  -b ]
    [ c  d ]                            [ -c   a ]

Notice the determinant sits in the denominator — this is the algebraic reason a zero determinant makes inversion impossible: you'd be dividing by zero, the same impossibility from Section 1.4's normalization pitfall, showing up again in a new context.

Worked problem

Problem: Find the inverse of A = [[3,1],[2,4]] (determinant already computed as 10 in Section 4.2), then verify it.

A⁻¹ = (1/10) * [ 4  -1 ]   = [ 0.4  -0.1 ]
                [-2   3 ]     [-0.2   0.3 ]

Verify: A @ A⁻¹ should equal I
[3,1] @ [0.4,-0.1]   = [3*0.4+1*(-0.2), 3*(-0.1)+1*0.3]   = [1.2-0.2, -0.3+0.3] = [1, 0]
[2,4]   [-0.2,0.3]     [2*0.4+4*(-0.2), 2*(-0.1)+4*0.3]     [0.8-0.8, -0.2+1.2]   [0, 1]

The result is exactly I, confirming the inverse is correct.

Larger matrices: Gauss-Jordan elimination

For 3×3 and larger, the direct formula becomes impractical (it involves computing a full grid of cofactors). Instead, extend Chapter 3's Gaussian elimination: augment A with the identity matrix, then perform row operations until the left side becomes the identity — whatever ends up on the right side is A⁻¹.

[ A | I ]  --row operations-->  [ I | A⁻¹ ]
Why this works

Every row operation is equivalent to multiplying by some simple matrix on the left. If a sequence of such operations transforms A into I, that same sequence of matrix multiplications, applied to I instead, gives you exactly A⁻¹ — because "the combination of operations that turns A into I" is, by definition, A⁻¹ itself (multiplying by A⁻¹ is what turns A into I). Running the identical operations on the identity matrix in parallel captures that combination directly.

In NumPy — and why you should rarely call this directly

import numpy as np
A = np.array([[3,1],[2,4]])
A_inv = np.linalg.inv(A)
print(A_inv)   # [[ 0.4 -0.1] [-0.2  0.3]]
Section 4.4

Why real code avoids computing the inverse directly

This is a genuinely important practical lesson that surprises people who've only seen the theory: even though x = A⁻¹b is mathematically correct, professional numerical code almost never computes A⁻¹ explicitly to solve a system. It uses Chapter 3's elimination-based approach instead (what np.linalg.solve actually does internally).

Why — two real reasons, not just style preference

1. It's slower. Computing a full inverse and then multiplying by b does substantially more arithmetic than directly solving for x via elimination — you're computing far more information (the entire inverse matrix) than you actually need (just one solution vector).

2. It's less numerically accurate. Every floating-point calculation introduces tiny rounding errors. Computing a full inverse involves more arithmetic operations than direct elimination, which means more opportunities for those tiny errors to accumulate and compound — especially for matrices that are "close to" singular (a very small, non-zero determinant), where this error amplification can become severe. This "closeness to singular" has a name — ill-conditioning — and Chapter 8 covers it properly.

import numpy as np
A = np.array([[3,1],[2,4]])
b = np.array([10, 12])

# Works, but not the recommended way:
x_slow = np.linalg.inv(A) @ b

# Preferred: solves directly via elimination, faster and more numerically stable
x_fast = np.linalg.solve(A, b)

print(x_slow, x_fast)   # same answer here, but solve() is the professional default
The practical rule to adopt now

Reach for np.linalg.inv() only when you genuinely need the inverse matrix itself for something later (some later chapters do). If your actual goal is just "solve this system for x," always prefer np.linalg.solve(A, b) — this single habit is one of the most common "textbook vs. real code" gaps engineers carry into their first job.

Wrap-up

Recap

  1. The inverse A⁻¹ of a matrix is the transformation that exactly undoes A: A⁻¹A = AA⁻¹ = I.
  2. Not every matrix is invertible — a matrix that collapses space onto a lower dimension (a line instead of a plane, etc.) destroys information that no inverse can recover.
  3. The determinant measures how much a matrix scales area/volume; a matrix is invertible if and only if its determinant is non-zero.
  4. A 2×2 inverse has a direct formula (swap diagonal, negate off-diagonal, divide by determinant); larger matrices use Gauss-Jordan elimination, extending Chapter 3's method.
  5. Real engineering code almost always solves Ax=b via direct elimination (np.linalg.solve) rather than explicitly computing A⁻¹ — it's faster and more numerically stable, especially for matrices close to singular.
Check yourself

Quick check

Question 1

A matrix has determinant 0. What does this tell you geometrically, and what does it tell you about solving Ax=b using A⁻¹?

Geometrically, the matrix collapses space onto a lower dimension (a line or point instead of a full plane), destroying information irreversibly. Since A⁻¹ doesn't exist for a singular matrix, you cannot solve via x = A⁻¹b — a different approach is needed (which may reveal no solution or infinite solutions, per Chapter 3).
Question 2

Why does professional code generally prefer np.linalg.solve(A, b) over np.linalg.inv(A) @ b, even though both give the same answer?

solve() is faster (it computes only what's needed for this one b, not the full inverse) and more numerically stable (fewer floating-point operations means less accumulated rounding error, which matters especially for near-singular matrices).
Question 3

What does a determinant of exactly 1 tell you about a transformation? What about -1?

A determinant of 1 means the transformation preserves area/volume exactly (like a pure rotation). A determinant of -1 also preserves area/volume magnitude, but flips orientation (like a reflection).

Eigenvalues & Eigenvectors

Take this chapter slowly; everything after it in your roadmap leans on it.

Section 6.1

What eigenvectors and eigenvalues actually are

The defining equation

For a square matrix A, an eigenvector v (a special, non-zero vector) and its corresponding eigenvalue λ (a scalar) satisfy:

Av = λv

Read this sentence carefully, because everything in this chapter depends on grasping it precisely: applying the full matrix transformation A to v produces exactly the same result as just scaling v by a plain number λ. Most vectors, transformed by a matrix, change direction — they get rotated, sheared, twisted. An eigenvector is a special direction that A doesn't rotate at all — it only stretches or shrinks (and flips, if λ is negative) along that exact same line.

An eigenvector is a direction a matrix "respects" — it changes length, never the line it lies on.
Why this is worth caring about at all

A general matrix transformation can look complicated — rotating, stretching, shearing all at once, hard to reason about directly. But if you describe the same transformation using its eigenvectors as your coordinate axes (recall Chapter 5: bases aren't unique), the transformation becomes almost embarrassingly simple: it's just scaling, independently, along each eigenvector direction, by that eigenvector's own eigenvalue. Eigenvalues and eigenvectors are how you find the "natural," simplest way to describe what a matrix does — Chapter 7 (diagonalization) makes this completely explicit.

Section 6.2

Finding eigenvalues — the characteristic equation

Rearranging the defining equation

Start from Av = λv. Move everything to one side:

Av - λv = 0
Av - λIv = 0        (insert the identity matrix, Chapter 2, so both terms are "matrix times v")
(A - λI)v = 0

This says: (A - λI), applied to v, gives the zero vector — but v itself is not the zero vector (eigenvectors are non-zero by definition). Recall Chapter 4/5's central fact: a matrix maps a non-zero vector to zero exactly when that matrix is singular — non-invertible, determinant zero, less than full rank. So:

The characteristic equation

(A - λI) must be singular, which (Chapter 4) means: det(A - λI) = 0. This is called the characteristic equation, and solving it for λ is how you find every eigenvalue of A — turning an eigenvalue problem directly into a determinant problem you already know how to solve.

Worked example — a 2×2 case

A = [ 4  1 ]
    [ 2  3 ]

A - λI = [ 4-λ    1  ]
         [  2    3-λ ]

det(A - λI) = (4-λ)(3-λ) - (1)(2)
            = 12 - 4λ - 3λ + λ² - 2
            = λ² - 7λ + 10

Set this equal to zero and factor:

λ² - 7λ + 10 = 0
(λ - 5)(λ - 2) = 0
λ = 5  or  λ = 2

This matrix has two eigenvalues: 5 and 2. (An n×n matrix always produces a degree-n polynomial here, so it always has exactly n eigenvalues, counting repeats and allowing complex numbers — Section 6.4 discusses what complex eigenvalues mean physically.)

In NumPy — you'll essentially never solve the characteristic polynomial by hand in practice

import numpy as np
A = np.array([[4,1],[2,3]])
eigvals, eigvecs = np.linalg.eig(A)
print(eigvals)   # [5. 2.] (order may vary)
Section 6.3

Finding the eigenvectors

Once you know an eigenvalue λ, finding its eigenvector is a direct application of Chapter 3: solve (A - λI)v = 0 — a system of equations, just like before, except the right-hand side is entirely zero (called a homogeneous system).

Continuing the worked example — finding the eigenvector for λ = 5

A - 5I = [ 4-5    1  ]   [ -1   1 ]
         [  2    3-5 ] = [  2  -2 ]

Solve (A-5I)v = 0:
-1*v1 + 1*v2 = 0    →   v2 = v1
 2*v1 - 2*v2 = 0    →   v2 = v1  (same equation, confirming redundancy — expected,
                                    since a singular matrix has dependent rows, Ch.5)

Any vector where v2 = v1 works — the eigenvector is only defined up to scaling (if v is an eigenvector, so is 2v, -v, or any non-zero multiple, since scaling doesn't change the line it lies on). A natural choice: v = (1, 1).

And for λ = 2

A - 2I = [ 4-2    1  ]   [ 2   1 ]
         [  2    3-2 ] = [ 2   1 ]

Solve: 2*v1 + v2 = 0  →  v2 = -2*v1
Eigenvector: v = (1, -2)
Verifying the result — always worth doing

Check: does Av = 5v for v = (1,1)?

Av = [4*1+1*1, 2*1+3*1] = [5, 5] = 5*(1,1) ✓

Confirmed — applying A to (1,1) really does just scale it by exactly 5, with no change of direction, exactly as the defining equation promised.

In NumPy

import numpy as np
A = np.array([[4,1],[2,3]])
eigvals, eigvecs = np.linalg.eig(A)
print(eigvals)          # [5. 2.]
print(eigvecs)          # columns are the eigenvectors (normalized to length 1 by default)
# eigvecs[:, 0] corresponds to eigvals[0], and so on
Pitfall

NumPy returns eigenvectors as columns of the returned matrix, already normalized to unit length (Chapter 1, Section 1.4) — so they may not match a "nice" hand-computed answer like (1,1) exactly, but they'll point along the same line. Don't expect a bitwise match to hand calculations; check direction (are they scalar multiples of each other?), not exact component values.

Section 6.4

Why eigenvalues determine stability

This is the payoff section — the reason this chapter matters so much for everything ahead in your roadmap (Control Systems II, Vehicle Dynamics, any state-space model). Skip nothing here.

The setup: a system evolving step by step

Picture a system whose state (a vector) evolves according to repeatedly applying the same matrix: state_next = A * state_current. This is exactly the structure of a discrete-time control system, a population model, or a simulation stepping forward in time. What happens to the state after many, many steps?

The key insight

If the current state happens to be exactly an eigenvector v of A, then one step later it's Av = λv — still pointing along the same direction, just scaled by λ. Apply A again: A(λv) = λ(Av) = λ(λv) = λ²v. After k steps, the state is λᵏv. Everything about the long-term behavior of the system, along that eigenvector direction, comes down to what λᵏ does as k grows — and any general starting state can be decomposed as a combination of the matrix's eigenvectors (this is exactly what a "basis," Chapter 5, gives you the right to do), so understanding each eigenvalue's behavior individually tells you the system's complete long-term behavior.

Reading stability directly from λ

Eigenvalue magnitudeBehavior of λᵏ as k growsSystem behavior along that direction
|λ| < 1Shrinks toward 0Stable — disturbances along this direction die out over time.
|λ| = 1Stays constantMarginally stable — neither grows nor decays; a borderline, delicate case.
|λ| > 1Grows without boundUnstable — any disturbance along this direction amplifies forever.
The same starting disturbance, three different fates — entirely determined by whether |λ| is below, at, or above 1.

Crucially: a system is genuinely stable only if EVERY eigenvalue has magnitude less than 1. A single unstable eigenvalue direction is enough to make the whole system eventually blow up, even if every other direction is perfectly stable — an unstable direction always wins in the long run because it grows without bound while stable directions shrink to nothing.

Complex eigenvalues — oscillation, not just growth/decay

Eigenvalues aren't always real numbers — they can be complex (involving i, the square root of -1), and they always come in conjugate pairs for real-valued matrices. Physically, a complex eigenvalue corresponds to oscillation — the system doesn't just grow or shrink, it spirals or rotates while doing so. The magnitude of the complex number still determines whether the oscillation grows (unstable), shrinks (stable, "damped"), or maintains constant amplitude (marginal) — the exact same |λ| rule from the table above, just applied to a complex number's magnitude instead of a real one.

Connecting directly to Control Systems II, which comes later in your roadmap

Recall the state-space form previewed back in Chapter 1: ẋ = Ax + Bu. When you design a state-feedback controller there (u = -Kx), the resulting closed-loop system becomes ẋ = (A - BK)x — and the entire point of choosing K carefully is to place the eigenvalues of (A - BK) in the stable region (for continuous-time systems, this means negative real parts rather than |λ|<1, but it's the exact same underlying idea). "Pole placement," the term used in that chapter, literally means "choosing K to put the eigenvalues where you want them." Everything in this section is the mathematical machinery underneath that entire chapter.

In NumPy — checking stability

import numpy as np
A = np.array([[0.5, 0.2], [0.1, 0.6]])
eigvals = np.linalg.eigvals(A)
print(eigvals)
is_stable = np.all(np.abs(eigvals) < 1)
print("Stable:", is_stable)
Section 6.5

A special case worth knowing: symmetric matrices

Recall Chapter 2, Section 2.5: a symmetric matrix (A = Aᵀ) shows up constantly in engineering as covariance matrices in sensor fusion and statistics. Symmetric matrices get a uniquely well-behaved guarantee that general matrices don't:

The guarantee

Every symmetric matrix has only real eigenvalues (never complex, unlike the general case from Section 6.4), and its eigenvectors can always be chosen to be mutually perpendicular (orthogonal — Chapter 1's dot-product-equals-zero condition) to each other. This isn't true for an arbitrary matrix — it's a special gift that symmetry provides.

Why this matters for Sensor Fusion, later in your roadmap

A covariance matrix (which describes how uncertain and how correlated your sensor errors are across different measurement axes) is always symmetric by construction. Guaranteed real eigenvalues means the "uncertainty along each principal direction" is always a sensible, real number (never a nonsensical complex quantity) — and guaranteed orthogonal eigenvectors means those principal directions of uncertainty are always perpendicular to each other, letting a Kalman filter (Sensor Fusion for Racing, later in this roadmap) cleanly separate uncertainty into independent, non-overlapping directions. This clean separation is precisely what makes the covariance ellipse visualizations used in sensor fusion diagrams mathematically well-defined.

In NumPy

import numpy as np
S = np.array([[4, 2], [2, 3]])   # symmetric: S == S.T
print(np.allclose(S, S.T))       # True

eigvals, eigvecs = np.linalg.eigh(S)   # 'eigh' is optimized specifically for symmetric matrices
print(eigvals)                          # both guaranteed real
print(eigvecs[:,0] @ eigvecs[:,1])      # ~0 -- confirms the eigenvectors are perpendicular
A practical tip

NumPy has two eigenvalue functions: np.linalg.eig (general, works on any square matrix) and np.linalg.eigh (specifically for symmetric/Hermitian matrices). Prefer eigh whenever you know your matrix is symmetric — it's faster and numerically more reliable, since it can exploit the guarantees above instead of handling the fully general (and harder) case.

Wrap-up

Recap

  1. An eigenvector v of matrix A is a special direction A doesn't rotate, only scales — captured by Av = λv, where λ is the corresponding eigenvalue.
  2. Eigenvalues are found by solving the characteristic equation det(A - λI) = 0; eigenvectors are then found by solving the homogeneous system (A-λI)v = 0 for each λ.
  3. Eigenvalues determine long-term stability of a system that repeatedly applies the same matrix: |λ|<1 shrinks (stable), |λ|=1 stays constant (marginal), |λ|>1 grows forever (unstable) — a system is only truly stable if every single eigenvalue satisfies this.
  4. Complex eigenvalues correspond to oscillation/spiraling behavior, not just plain growth or decay; the same magnitude rule for stability still applies.
  5. Symmetric matrices (like covariance matrices in sensor fusion) are guaranteed real eigenvalues and perpendicular eigenvectors — a special, well-behaved case worth recognizing.
  6. This chapter is the mathematical foundation underneath Control Systems II's pole placement and Sensor Fusion's covariance handling — both reappear directly later in your roadmap.
Check yourself

Quick check

Question 1

What does the equation Av = λv actually say about how A affects the vector v, in plain language?

It says A doesn't change v's direction at all — it only stretches, shrinks, or flips v along the same line it already lies on, by the factor λ.
Question 2

A discrete-time system's matrix has eigenvalues 0.8 and 1.3. Is the overall system stable? Why or why not?

Unstable — even though 0.8 is stable on its own (|λ|<1), the eigenvalue 1.3 has |λ|>1, meaning disturbances along that eigenvector's direction grow without bound over time, and that single unstable direction is enough to make the whole system unstable.
Question 3

Why does NumPy provide a separate function (eigh) just for symmetric matrices instead of always using the general eig?

Symmetric matrices are guaranteed to have real eigenvalues and orthogonal eigenvectors, a special structure that eigh can exploit for better speed and numerical reliability than the fully general algorithm eig has to use for arbitrary matrices.

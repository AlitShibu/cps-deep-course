Diagonalization & Decompositions

Chapter 6 promised that eigenvectors let you describe a matrix's action in its "natural," simplest form. This chapter makes that completely explicit — diagonalization is the formal procedure for rewriting a matrix using its own eigenvectors as the coordinate axes, and a brief look at other decompositions previews ideas you'll meet again in more advanced work.

Section 7.1

Diagonalization

The construction

Suppose an n×n matrix A has n linearly independent eigenvectors (this doesn't always happen, but it's common — Section 7.2 covers what to do when it doesn't). Collect those eigenvectors as the columns of a matrix P, and collect the corresponding eigenvalues along the diagonal of a matrix D (zeros everywhere else — recall Chapter 2's "diagonal matrix" definition). Then:

A = PDP⁻¹

This is called diagonalizing A. Read it using Chapter 2's transformation-composition idea (Section 2.4, "rightmost happens first"): P⁻¹ switches you into the eigenvector coordinate system, D does the transformation there (which, in that system, is just independent scaling along each axis — as simple as a transformation can possibly be), and P switches you back to the original coordinate system.

Diagonalization: the same overall transformation, decomposed into "change viewpoint → simple scaling → change back."

Full worked example, continuing Chapter 6's matrix

Recall from Chapter 6: A = [[4,1],[2,3]] has eigenvalues 5, 2 with eigenvectors (1,1) and (1,-2).

P = [ 1   1 ]     D = [ 5  0 ]
    [ 1  -2 ]         [ 0  2 ]

Compute P⁻¹ using Chapter 4's 2×2 formula (det(P) = 1×(-2) - 1×1 = -3):

P⁻¹ = (1/-3) * [ -2  -1 ]   = [ 2/3   1/3 ]
                [ -1   1 ]     [ 1/3  -1/3 ]

Verify PDP⁻¹ reconstructs A (worth doing once by hand to build trust in the machinery — in practice you'd always use code):

PD = [1,1;1,-2] @ [5,0;0,2] = [5, 2; 5, -4]
PDP⁻¹ = [5,2; 5,-4] @ [2/3,1/3; 1/3,-1/3]
      = [5*2/3+2*1/3, 5*1/3+2*(-1/3); 5*2/3+(-4)*1/3, 5*1/3+(-4)*(-1/3)]
      = [10/3+2/3, 5/3-2/3; 10/3-4/3, 5/3+4/3]
      = [4, 1; 2, 3]  ✓ exactly A
Why bother — what diagonalization is actually used for

The huge practical payoff: computing Aᵏ (A applied k times in a row — exactly the repeated-step scenario from Chapter 6's stability discussion) is expensive to do directly for large k, but trivial once diagonalized: Aᵏ = PDᵏP⁻¹, and raising a diagonal matrix to a power just means raising each diagonal entry to that power independently — no matrix multiplication needed at all for that middle step. This is exactly how you'd efficiently predict a system's state far into the future, or analytically prove a system converges, without simulating every single intermediate step.

In NumPy

import numpy as np
A = np.array([[4,1],[2,3]])
eigvals, P = np.linalg.eig(A)
D = np.diag(eigvals)
P_inv = np.linalg.inv(P)

A_reconstructed = P @ D @ P_inv
print(np.allclose(A, A_reconstructed))   # True

# The payoff: A^10 the easy way
A_10 = P @ np.diag(eigvals**10) @ P_inv
print(np.allclose(A_10, np.linalg.matrix_power(A, 10)))   # True
Section 7.2

When diagonalization isn't possible

Diagonalization requires n independent eigenvectors for an n×n matrix. This doesn't always happen — a matrix can have a repeated eigenvalue that doesn't come with enough independent eigenvectors to go around. Such a matrix is called defective, and it cannot be diagonalized.

A concrete example

Matrix: A = [[2,1],[0,2]]. Its characteristic equation: det(A-λI) = (2-λ)² = 0, giving a repeated eigenvalue λ=2 (only one distinct value, appearing twice).

Solving (A-2I)v=0: [[0,1],[0,0]]v=0 → only v2=0 is required, so eigenvectors are all multiples of (1,0) — just one independent direction, even though the eigenvalue is "repeated twice." A 2×2 matrix needs 2 independent eigenvectors to diagonalize; this one only provides 1. Not diagonalizable.

You don't need to fully resolve this to move forward

Non-diagonalizable matrices can still be simplified using a related but more advanced tool (the Jordan normal form), which is beyond what this course needs — the important practical takeaway for your CPS work is simply: check whether a matrix is diagonalizable before relying on the PDP⁻¹ trick (NumPy's eig will still run, but the resulting eigenvectors won't be independent enough to reconstruct A via PDP⁻¹ if it's defective). In real engineering code, this is rarely a practical roadblock — most physically-motivated matrices you'll encounter (especially symmetric ones, Section 6.5) diagonalize cleanly.

Section 7.3

A preview: Singular Value Decomposition (SVD)

Diagonalization has a real limitation: it only applies to square matrices, and even then, only diagonalizable ones (Section 7.2). SVD is a decomposition that works for any matrix whatsoever — square or not, diagonalizable or not — which is why it's one of the most broadly useful tools in all of applied linear algebra. This course won't go deep into SVD's mechanics (that's genuinely a more advanced topic), but it's worth knowing what it is and why it matters, since you'll very likely meet it again.

A = UΣVᵀ

where U and V are matrices with perpendicular columns (orthogonal, in the Chapter 1 sense), and Σ is diagonal, holding the singular values — always non-negative real numbers, always guaranteed to exist, no matter how "badly behaved" A is.

Where you'll actually meet this later

SVD underlies PCA (Principal Component Analysis), a standard technique for finding the "most important directions" in noisy, high-dimensional sensor or telemetry data — directly relevant to Data Acquisition & Telemetry and TinyML later in your roadmap. It's also the industry-standard tool for numerically robust least-squares fitting when a system is over- or under-determined (more equations than unknowns, or vice versa) — a very common real-world situation Chapter 3's clean square-system examples didn't cover. For now, simply recognize the name and the shape of the idea: SVD generalizes diagonalization to work everywhere, at the cost of needing two different matrices (U and V) instead of the one Chapter 7 has been using (P).

In NumPy — just to see it exists

import numpy as np
A = np.array([[1,2],[3,4],[5,6]])   # non-square: 3x2, diagonalization doesn't even apply here
U, S, Vt = np.linalg.svd(A)
print(S)   # the singular values -- always real, always non-negative, always exist
Wrap-up

Recap

  1. Diagonalization rewrites A = PDP⁻¹, where P's columns are A's eigenvectors and D is a diagonal matrix of A's eigenvalues — expressing A's transformation as "change viewpoint, scale independently along each axis, change back."
  2. The practical payoff is computing Aᵏ cheaply: Aᵏ = PDᵏP⁻¹, turning an expensive repeated matrix multiplication into simple per-entry exponentiation of D.
  3. Not every matrix is diagonalizable — a defective matrix has a repeated eigenvalue without enough independent eigenvectors to go with it.
  4. SVD (A = UΣVᵀ) generalizes the idea to work on any matrix whatsoever, at the cost of needing two orthogonal matrices instead of one — it underlies PCA and robust least-squares fitting, both of which reappear later in your roadmap.
Check yourself

Quick check

Question 1

In A = PDP⁻¹, what do the columns of P represent, and what does D contain?

P's columns are A's eigenvectors; D is a diagonal matrix holding A's corresponding eigenvalues.
Question 2

Why is computing A^50 so much cheaper once A is diagonalized, compared to multiplying A by itself 50 times directly?

A^50 = P D^50 P⁻¹, and raising a diagonal matrix to a power just means raising each diagonal entry independently — no repeated full matrix multiplications needed for the expensive middle step.
Question 3

What key limitation does SVD not have, that diagonalization does?

SVD works on any matrix, including non-square ones and non-diagonalizable (defective) square matrices — diagonalization requires a square, diagonalizable matrix.

NumPy I — Arrays & Vectorization

This is the section you specifically asked for. This chapter builds it from the ground up.

Section 4.1

What NumPy is, and why Python needs it at all

Installing it

pip install numpy

Unlike print(), lists, or dictionaries (Chapter 2), NumPy is not built into Python — it's a third-party package you install once per project (ideally inside a virtual environment, covered in Chapter 9). Once installed, you import it, by overwhelming convention, as np:

import numpy as np

The problem NumPy solves

A Python list (Chapter 2) is flexible — it can hold mixed types, grow and shrink freely — but that flexibility has a real cost: each element is actually a separate Python object, scattered in memory, with its own type-checking overhead every time you touch it. Looping over a million-element list in pure Python, doing arithmetic on each element one at a time, is genuinely slow — slow enough to matter for real engineering-scale data.

import numpy as np

# A NumPy array -- looks similar to a list, but is fundamentally different underneath
arr = np.array([1, 2, 3, 4, 5])
print(arr)          # [1 2 3 4 5]
print(type(arr))     # <class 'numpy.ndarray'>
print(arr.dtype)      # int64 -- EVERY element must be the SAME type, unlike a Python list
A NumPy array is, underneath Python's surface, essentially the C array from C Chapter 5 — contiguous, uniformly-typed memory.
Why this connects directly to your C course

A NumPy array is implemented internally in C, storing its data exactly like C Chapter 5's contiguous array — one uniform type, packed tightly, no per-element Python object overhead. Operations on a NumPy array run as compiled C loops under the hood, not interpreted Python bytecode. This is precisely why NumPy is fast despite Python itself being an interpreted language (Chapter 1's tradeoff) — you write Python syntax, but the actual number-crunching happens at C speed, one contiguous block at a time.

Section 4.2

Vectorization — the single most important NumPy idea

The slow way vs. the NumPy way

import numpy as np
import time

n = 1_000_000
python_list = list(range(n))
numpy_array = np.arange(n)

# The slow way -- a Python-level loop, processing one element at a time
start = time.time()
result_list = [x * 2 for x in python_list]     # Chapter 2's list comprehension
print(f"Python loop: {time.time() - start:.4f}s")

# The NumPy way -- ONE operation, applied to the whole array at once
start = time.time()
result_array = numpy_array * 2                   # no loop written at all!
print(f"NumPy vectorized: {time.time() - start:.4f}s")

# Typical result: NumPy is roughly 20-50x faster for this kind of operation
Why this works — vectorization, precisely defined

Vectorization means replacing an explicit element-by-element loop with a single operation applied to an entire array at once. numpy_array * 2 doesn't loop in Python at all — it dispatches to a single, tight, compiled C loop (recall Section 4.1) that processes every element without ever returning control to Python's slower interpreter between elements. The Python-level loop, by contrast, pays Python's interpretation overhead once per element — a million times over, for a million-element array. This is the central skill this chapter and the next build: learning to think in terms of "what operation do I want on the whole array" rather than "what do I do to each element."

Element-wise arithmetic — the basic vectorized operations

a = np.array([1, 2, 3, 4])
b = np.array([10, 20, 30, 40])

print(a + b)     # [11 22 33 44] -- element-wise addition, no loop
print(a * b)      # [10 40 90 160] -- element-wise multiplication
print(b / a)       # [10. 10. 10. 10.]
print(a ** 2)        # [1 4 9 16] -- every element squared, at once
print(a > 2)          # [False False  True  True] -- a BOOLEAN array, element-wise comparison!
A genuine mental shift from Chapter 2's lists

python_list * 2 (a plain list, not a NumPy array) does something completely different — it duplicates the list's contents ([1,2,3] * 2 gives [1,2,3,1,2,3]), not multiply each element. This is a real, easy-to-hit trap when moving between plain Python lists and NumPy arrays — the same syntax means genuinely different things depending on which type you're actually holding, and it's worth double-checking which one you have whenever this distinction matters.

Section 4.3

Boolean masking — filtering without a loop

Section 4.2 ended with a > 2 producing a boolean array. This turns out to be extraordinarily useful — you can use a boolean array to directly index another array, selecting only the elements where the mask is True:

readings = np.array([21.5, 22.0, 45.8, 21.8, 23.1, 99.9, 22.4])   # two are clearly bad sensor glitches

mask = readings < 30                    # boolean array: True where the condition holds
print(mask)                                # [ True  True False  True  True False  True]

clean_readings = readings[mask]           # select only the elements where mask is True
print(clean_readings)                       # [21.5 22.  21.8 23.1 22.4]

# Often written in one line, without a separate named mask variable:
clean_readings = readings[readings < 30]
print(clean_readings)                        # same result

# Modify in place, using a mask -- replace all glitch values with NaN (Not-a-Number)
readings[readings > 30] = np.nan
print(readings)   # [21.5 22.  nan 21.8 23.1 nan 22.4]
What this replaces, and why it matters so much for engineering data

This directly replaces a C-style (or plain-Python-list-style) loop: "for each element, check a condition, and if it passes, keep it" — collapsed into one expression with no explicit loop or index variable anywhere. This exact pattern — filtering out sensor glitches, outliers, or invalid readings — is one of the most common real operations on engineering and telemetry data (your Motorsport track's telemetry analysis leans on exactly this), and boolean masking is the idiomatic, fast way to do it in NumPy.

Combining conditions

data = np.array([15, 22, 8, 30, 45, 12, 28])

# Use & (bitwise AND, C Chapter 10) and | for combining masks --
# NOT Python's 'and'/'or', which don't work element-wise on arrays!
in_range = data[(data > 10) & (data < 30)]
print(in_range)   # [15 22 12 28]
Why & and not 'and'

Python's and/or (Chapter 1) expect a single True/false value on each side, not an entire array — using them on two boolean arrays raises an error, since NumPy can't collapse a whole array into one true/false answer for the purpose Python's and requires. The bitwise operators &/| (recall C Chapter 10's bitwise chapter — same operators, same underlying bit-level logic) work element-wise on arrays instead, which is exactly the behavior needed here. The parentheses around each condition are required too — without them, operator precedence parses the expression incorrectly.

Section 4.4

Creating arrays, and built-in statistics

Common ways to create an array

np.array([1, 2, 3])              # from an existing Python list
np.zeros(5)                        # [0. 0. 0. 0. 0.]
np.ones(5)                          # [1. 1. 1. 1. 1.]
np.arange(0, 10, 2)                  # [0 2 4 6 8] -- like Python's range(), but returns an array
np.linspace(0, 1, 5)                  # [0.   0.25 0.5  0.75 1.  ] -- 5 evenly spaced points from 0 to 1
np.random.rand(5)                      # 5 random values between 0 and 1

Aggregation — collapsing an array to a summary statistic

data = np.array([21.5, 22.0, 21.8, 23.1, 22.4])

print(data.sum())      # 110.8
print(data.mean())      # 22.16
print(data.std())        # standard deviation
print(data.min())         # 21.5
print(data.max())          # 23.1
print(data.argmax())        # 3 -- the INDEX of the maximum value, not the value itself
Why these matter beyond convenience

Every one of these is itself vectorized — .mean() doesn't loop in Python to sum and divide, it uses the same compiled-C-loop mechanism from Section 4.2. This matters because these aggregation functions are the actual building blocks of real engineering analysis: computing a sensor's average reading, its noise level (standard deviation), or finding when the peak value occurred (argmax) are all one-line operations here, versus multi-line manual loops in C (recall C Chapter 5's array-average worked example, which needed an explicit loop and manual sum-then-divide) or even in pure Python without NumPy.

Worked problem — cleaning and summarizing a noisy sensor dataset 
import numpy as np

raw = np.array([21.5, 22.0, -999, 21.8, 23.1, -999, 22.4, 45.0, 22.1])
# -999 is a common sensor "no data" sentinel value; 45.0 is a plausible-but-wrong outlier

# Step 1: remove the obvious sentinel values
valid = raw[raw != -999]
print("After removing sentinels:", valid)

# Step 2: remove statistical outliers -- anything more than 2 standard deviations from the mean
mean, std = valid.mean(), valid.std()
clean = valid[np.abs(valid - mean) < 2 * std]
print("After removing outliers:", clean)

print(f"Final average: {clean.mean():.2f}")
print(f"Final std dev: {clean.std():.2f}")

What's happening in Step 2: np.abs(valid - mean) computes, element-wise, how far each reading is from the mean (a vectorized subtraction followed by a vectorized absolute value — no loop written). Comparing that against 2 * std produces a boolean mask (Section 4.3) that's True for readings within two standard deviations — a common, simple outlier-rejection rule — and indexing valid with that mask keeps only the readings that pass. This entire multi-step cleaning pipeline is four lines, each fully vectorized, with no explicit loop anywhere.

Wrap-up

Recap

  1. NumPy is a separate library (pip install numpy), not built into Python — but treated as standard equipment for engineering work, since it's what makes Python fast enough for real numerical computation.
  2. A NumPy array is uniform-typed and stored contiguously in memory — essentially C's array (C Chapter 5) underneath Python's surface — which is why operations on it run as compiled C loops, not slow interpreted Python.
  3. Vectorization — applying one operation to a whole array at once — replaces explicit element-by-element loops, and is typically tens of times faster for large arrays.
  4. Boolean masking (arr[arr > threshold]) filters an array without writing a loop — the standard idiom for removing outliers, sentinels, or invalid readings from real data.
  5. Combine boolean conditions with &/| (bitwise, element-wise), never Python's and/or, which don't work correctly on whole arrays.
  6. Aggregation methods (.mean(), .std(), .max(), .argmax()) are themselves vectorized, collapsing an entire array into a summary statistic in one call.
Check yourself

Quick check

Question 1

Why is numpy_array * 2 typically dramatically faster than looping over a Python list and multiplying each element by 2?

The NumPy operation dispatches to a single compiled C loop that processes the entire contiguous array without returning control to Python's interpreter between elements. The Python-level loop pays Python's interpretation overhead once per element, which adds up significantly across a large array.
Question 2

What does readings[readings > 100] = np.nan actually do, described in plain terms?

It creates a boolean mask that's True wherever a reading exceeds 100, then uses that mask to select exactly those elements in the readings array and replace them with NaN (Not-a-Number) — all in one vectorized operation, with no explicit loop.
Question 3

Why does combining two boolean array conditions require & instead of Python's and?

Python's "and" expects to collapse each side into a single True/False value, which doesn't make sense for an entire array of booleans. The bitwise & operator works element-wise instead, comparing corresponding elements from each boolean array and producing a new boolean array — exactly the behavior needed to combine two array-wide conditions.

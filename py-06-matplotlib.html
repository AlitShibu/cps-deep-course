Matplotlib — Visualizing Engineering Data

Every NumPy array you've built in the last two chapters has been a wall of numbers to inspect by eye. Matplotlib turns that wall of numbers into something you can actually see a pattern in — and it's the same library, at least in spirit, that produced most of the diagrams in the Linear Algebra course you already finished (hand-drawn SVGs there; here, plotted directly from your own data).

Section 6.1

Your first plot, and the anatomy of a figure

pip install matplotlib
import matplotlib.pyplot as plt   # 'plt' is the near-universal convention, like np for NumPy
import numpy as np

x = np.linspace(0, 10, 100)         # Chapter 4 -- 100 evenly spaced points from 0 to 10
y = np.sin(x)                          # vectorized -- sin applied to all 100 points at once

plt.plot(x, y)
plt.xlabel("Time (s)")
plt.ylabel("Amplitude")
plt.title("A sine wave")
plt.savefig("sine_wave.png")            # saves to a file
plt.show()                                # opens an interactive window (in a script; inline in notebooks)
Every plot has this same skeleton: a figure containing axes, with labels, a title, and one or more plotted series.
Why plt.plot(x, y) is exactly what it looks like

plot(x, y) takes two equal-length arrays and draws a line connecting (x[0],y[0]) to (x[1],y[1]) to (x[2],y[2]), and so on — literally connect-the-dots. This is why x and y from Chapter 4's vectorized computation slot in directly: np.linspace generates the x-coordinates, and a vectorized function (np.sin) generates the matching y-coordinates in one shot, with no explicit loop needed to build either array.

Multiple series on one plot

x = np.linspace(0, 10, 100)
plt.plot(x, np.sin(x), label="sin(x)")
plt.plot(x, np.cos(x), label="cos(x)")
plt.legend()             # shows the labels from above, in a legend box
plt.grid(True)             # adds gridlines -- often makes engineering plots easier to read precisely
plt.show()
Section 6.2

The plot types you'll actually use

Scatter plots — for discrete data points, not a continuous line

x = np.random.rand(50) * 100     # 50 random x-values
y = 2 * x + np.random.randn(50) * 10   # a rough linear relationship, plus noise

plt.scatter(x, y, alpha=0.6)       # alpha = transparency, helps when points overlap
plt.xlabel("Input")
plt.ylabel("Output")
plt.show()

Use scatter instead of plot when consecutive data points aren't meaningfully connected — individual measurements, sensor samples at irregular times, or anywhere a connecting line would visually imply a relationship between adjacent points that doesn't actually exist.

Bar charts — comparing discrete categories

sensors = ["Temp", "Humidity", "Pressure", "Light"]
readings = [23.5, 45.0, 1013.2, 850]

plt.bar(sensors, readings)
plt.ylabel("Reading")
plt.title("Current sensor values")
plt.show()

Subplots — multiple plots in one figure

fig, axes = plt.subplots(2, 1, figsize=(8, 6))   # 2 rows, 1 column of plots

axes[0].plot(x_time, temperature_data)
axes[0].set_title("Temperature over time")
axes[0].set_ylabel("°C")

axes[1].plot(x_time, humidity_data)
axes[1].set_title("Humidity over time")
axes[1].set_ylabel("%")
axes[1].set_xlabel("Time (s)")

plt.tight_layout()   # prevents subplot titles/labels from overlapping each other
plt.show()
Why subplots return an array you index into

plt.subplots(2, 1) returns two things: the overall fig (the whole canvas) and axes — for a 2×1 grid, a NumPy-array-like structure (Chapter 5's indexing applies directly: axes[0] is the first subplot, axes[1] the second). This is genuinely the standard way to lay out multiple related plots — comparing several sensor channels stacked vertically, exactly as your Motorsport telemetry work will need, is a one-line loop over an axes array rather than manually positioning each plot by hand.

Section 6.3

Worked problem — visualizing a cleaned sensor dataset

Recall Chapter 4, Section 4.4's worked problem: cleaning a noisy sensor dataset by removing sentinels and statistical outliers. Seeing the before/after visually is far more convincing than reading the printed numbers.

import numpy as np
import matplotlib.pyplot as plt

np.random.seed(0)
raw = np.concatenate([
    23 + np.random.randn(50) * 0.5,     # 50 normal-ish readings around 23
    [45, -999, 44, -999]                  # a few outliers and sentinels mixed in
])

valid = raw[raw != -999]
mean, std = valid.mean(), valid.std()
clean = valid[np.abs(valid - mean) < 2 * std]

fig, axes = plt.subplots(1, 2, figsize=(10, 4))

axes[0].plot(raw, marker='o', linestyle='-', alpha=0.7)
axes[0].set_title(f"Raw data (n={len(raw)})")
axes[0].set_ylabel("Reading")
axes[0].grid(True)

axes[1].plot(clean, marker='o', linestyle='-', color='green', alpha=0.7)
axes[1].set_title(f"Cleaned data (n={len(clean)})")
axes[1].grid(True)

plt.tight_layout()
plt.savefig("cleaning_comparison.png")
plt.show()

What this demonstrates: the left subplot's y-axis will stretch dramatically to accommodate the 45 and -999 outliers, visually compressing the real, meaningful data into a flat-looking band near the bottom — while the right subplot, freed of those extremes, shows the actual variation in the real readings clearly. This side-by-side comparison is a genuinely standard way to communicate "here's why data cleaning mattered" in an engineering report or presentation, and it's built entirely from Chapter 4's masking code plus this chapter's subplot layout.

Wrap-up

Recap

  1. Matplotlib is a separate library (pip install matplotlib), conventionally imported as plt, that turns NumPy arrays into visible plots.
  2. plt.plot(x, y) connects points with a line — appropriate for continuous data; plt.scatter is for discrete, unconnected points; plt.bar compares categories.
  3. Every plot shares the same skeleton — a figure, axes, labels, a title, and one or more data series, optionally with a legend and gridlines.
  4. plt.subplots(rows, cols) returns a figure and an array of axes you can index into (Chapter 5's indexing) to build multi-panel comparisons.
  5. Visualizing a before/after data-cleaning comparison (as in the worked problem) is often far more convincing than printed summary statistics alone — a core skill for actually communicating engineering analysis, not just performing it.
Check yourself

Quick check

Question 1

You have irregular, individually-measured sensor samples where consecutive points aren't meaningfully related. Should you use plt.plot or plt.scatter, and why?

plt.scatter — plt.plot draws a connecting line between consecutive points, which visually implies a relationship or trend between them that doesn't actually exist for unrelated, individually-measured samples.
Question 2

What do plt.subplots(2, 1) return, and how do you access the second subplot specifically?

It returns a tuple: the overall figure (fig) and an array-like collection of axes objects. For a 2x1 grid, the second subplot is accessed as axes[1], using the same zero-based indexing as any other array (Chapter 5).
Question 3

Why might visualizing a before/after data-cleaning comparison be more effective than just printing the mean and standard deviation of each?

A plot immediately shows the shape and scale of the problem — how outliers distort the visible range, and how much clearer the real variation becomes once removed — which is often more intuitively convincing to a reader than numeric statistics alone, especially when communicating results to someone who wasn't involved in the analysis itself.

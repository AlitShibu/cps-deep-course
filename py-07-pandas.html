Pandas — Tabular & Time-Series Data

NumPy (Chapters 4-5) is built for arrays of uniform numbers. Real engineering data is rarely that clean — it's a table with named columns of different types, timestamps, and gaps. Pandas is the library built specifically for that shape of data, and it's what you'll actually reach for when analyzing telemetry logs, CSVs, or any spreadsheet-like dataset.

Section 7.1

The DataFrame — a table, not just an array

pip install pandas
import pandas as pd    # the near-universal convention, like np and plt

data = {
    "sensor": ["temp", "temp", "humidity", "humidity"],
    "value": [23.5, 24.1, 45.0, 44.8],
    "time": [1, 2, 1, 2]
}
df = pd.DataFrame(data)
print(df)
#     sensor  value  time
# 0     temp   23.5     1
# 1     temp   24.1     2
# 2  humidity   45.0     1
# 3  humidity   44.8     2
How a DataFrame relates to what you already know

A DataFrame is essentially built from Chapter 2's dictionary (each key becomes a named column) combined with Chapter 4's NumPy arrays (each column is internally stored as one, giving vectorized speed) — but organized as rows and labeled columns, like a spreadsheet or a database table, rather than a flat list of numbers. This is precisely the missing piece between NumPy's uniform numeric arrays and the messy, mixed-type, labeled reality of real telemetry logs and CSV exports.

Reading real data — CSV files

df = pd.read_csv("telemetry.csv")
print(df.head())          # first 5 rows -- a quick sanity check on any new dataset
print(df.info())            # column names, types, and non-null counts, all at once
print(df.describe())         # count, mean, std, min, max, quartiles -- for every numeric column

read_csv directly replaces C Chapter 11's manual fopen/line-parsing entirely — one line reads, type-infers, and structures an entire file, instead of a hand-written parsing loop.

Selecting rows and columns

print(df["value"])                    # one column, as a Series (a labeled 1D array)
print(df[["sensor", "value"]])           # multiple columns, as a smaller DataFrame

print(df[df["sensor"] == "temp"])          # BOOLEAN MASKING -- exactly Chapter 4, Section 4.3,
                                              # now filtering rows of a table instead of a 1D array

print(df.loc[0])                             # row by LABEL (index 0)
print(df.iloc[0])                             # row by POSITION (the first row, regardless of label)
Boolean masking, generalized

This is the exact same idea from Chapter 4, Section 4.3 — df[condition] keeps only the rows where condition is True — just now filtering entire rows of a labeled table instead of elements of a plain array. If Chapter 4's masking felt natural, this should too; it's the identical mental model, one level up in structure.

Section 7.2

groupby — aggregating by category

df = pd.DataFrame({
    "sensor": ["temp", "temp", "temp", "humidity", "humidity", "humidity"],
    "value": [23.5, 24.1, 23.8, 45.0, 44.8, 45.2]
})

print(df.groupby("sensor")["value"].mean())
# sensor
# humidity    45.00
# temp        23.80
# Name: value, dtype: float64

print(df.groupby("sensor")["value"].agg(["mean", "std", "min", "max"]))   # several stats at once
groupby follows "split, apply, combine": split rows by category, apply an aggregation to each group, combine into one summary table.
What this replaces

Without groupby, computing "average per sensor" would mean manually finding each unique sensor name (Chapter 2's sets), looping over rows, and accumulating sums and counts per category by hand — exactly the pattern the telemetry-log worked problem in Chapter 2 built manually with a plain dictionary. groupby is that entire pattern, generalized and optimized, in one line — and it's genuinely one of the most-used operations in real engineering data analysis, since "summarize by category" (per sensor, per test run, per vehicle, per driver) is an extremely common question to ask of real data.

Section 7.3

Time series — Pandas' other specialty

df = pd.DataFrame({
    "timestamp": pd.to_datetime(["2026-01-01 10:00", "2026-01-01 10:01", "2026-01-01 10:02"]),
    "speed": [45.2, 46.8, 44.1]
})
df = df.set_index("timestamp")     # make the timestamp the row index, not just a column
print(df)

resampled = df.resample("1min").mean()    # already 1-per-minute here, but this is how you'd
                                             # DOWNSAMPLE denser data, e.g. from 10Hz to 1Hz

df["speed_smoothed"] = df["speed"].rolling(window=2).mean()   # a MOVING AVERAGE --
                                                                  # exactly Chapter 1 of Python's
                                                                  # earlier convolve-based smoothing,
                                                                  # now built in directly
print(df)
Why dedicated time-series support matters for your Motorsport track

pd.to_datetime understands real calendar dates and times (not just plain numbers), resample can cleanly convert between sampling rates (crucial when combining sensors that report at different frequencies — exactly the Sensor Fusion problem from your roadmap), and .rolling().mean() is a one-line moving average, directly replacing the manual convolution-based smoothing from earlier in this Python course. Telemetry data (Data Acquisition & Telemetry, later in your roadmap) is fundamentally time-series data, and this is the standard toolkit for handling it.

Section 7.4

Worked problem — comparing two race laps

Recall the CPS study guide's Data Acquisition & Telemetry topic: comparing two laps by distance, not time, using NumPy interpolation directly. Here's the same problem, solved far more concisely with Pandas.

import pandas as pd

lap1 = pd.DataFrame({"time": [0, 1, 2, 3], "speed": [0, 45, 78, 95]})
lap2 = pd.DataFrame({"time": [0, 1, 2, 3], "speed": [0, 42, 80, 98]})

lap1["distance"] = (lap1["speed"] * lap1["time"].diff().fillna(0)).cumsum()
lap2["distance"] = (lap2["speed"] * lap2["time"].diff().fillna(0)).cumsum()

merged = pd.merge_asof(lap1.sort_values("distance"), lap2.sort_values("distance"),
                          on="distance", suffixes=("_lap1", "_lap2"))

merged["speed_diff"] = merged["speed_lap1"] - merged["speed_lap2"]
print(merged[["distance", "speed_lap1", "speed_lap2", "speed_diff"]])

biggest_gain_row = merged.loc[merged["speed_diff"].idxmax()]
print(f"Biggest gain at distance {biggest_gain_row['distance']:.1f}m: "
      f"+{biggest_gain_row['speed_diff']:.1f} km/h")
What pd.merge_asof is doing, and why it fits this problem exactly

merge_asof aligns two tables by finding the nearest matching value in a sorted column (here, distance) rather than requiring an exact match — precisely the "align by distance, not time" problem from the original telemetry worked example, but expressed as a single built-in operation instead of manually writing np.interp calls for every column you want compared. .idxmax() returns the label of the row with the maximum value in a column (compare to Chapter 4/5's argmax, which returns a plain position) — using .loc with that label retrieves the entire matching row, giving you every column's value at the point of biggest difference in one step.

Wrap-up

Recap

  1. A DataFrame is a labeled table — dictionaries' named-key structure (Chapter 2) combined with NumPy's vectorized columns (Chapter 4) — built for the mixed-type, labeled reality of real datasets.
  2. pd.read_csv replaces manual file-parsing (C Chapter 11's discipline) with one line that reads, type-infers, and structures an entire file.
  3. Boolean masking on a DataFrame (df[condition]) is the exact same idea as Chapter 4's array masking, applied to whole rows of a table.
  4. groupby follows "split, apply, combine" — splitting rows by category, aggregating each group, and combining into one summary — replacing manual dictionary-based counting/summing.
  5. Pandas has dedicated time-series support: to_datetime, resample (changing sampling rate), and .rolling().mean() (a built-in moving average) — directly relevant to telemetry and sensor-fusion work later in the roadmap.
  6. merge_asof aligns two tables by nearest value in a sorted column — the concise, built-in version of manually interpolating and comparing two datasets by a shared axis like distance.
Check yourself

Quick check

Question 1

How does a Pandas DataFrame relate to concepts you already know from Chapters 2 and 4?

It combines a dictionary's named-key structure (each key becomes a labeled column) with NumPy's vectorized array storage (each column is internally a fast, uniformly-typed array) — giving you labeled, mixed-type tabular data with NumPy-level performance for numeric operations.
Question 2

What does groupby("sensor")["value"].mean() actually compute, described in plain terms?

It splits the rows into groups by their sensor value, computes the mean of the value column within each group separately, and combines those per-group results into one summary — the average reading for each distinct sensor type.
Question 3

Why is merge_asof, not a regular exact-match merge, the right tool for aligning two laps' telemetry by distance?

Two different laps almost never have measurements at exactly the same distance values, since each lap's samples come from independent points in time. merge_asof aligns rows by their NEAREST matching value in the sorted distance column, rather than requiring an exact match, which is essential when comparing two independently-sampled datasets along a shared continuous axis.

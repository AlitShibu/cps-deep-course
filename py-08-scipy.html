Section 8.2

Filtering — implementing Signals & Systems for real

Recall the CPS study guide's Signals & Systems worked example: separating a real 5Hz signal from 50Hz electrical noise using a Butterworth low-pass filter. Here's that exact code, now with full context for every piece.

import numpy as np
from scipy.signal import butter, filtfilt

fs = 500   # sampling rate, Hz -- recall the Nyquist theorem from the study guide:
             # this must be more than 2x the fastest frequency you care about

t = np.arange(0, 2, 1/fs)
signal = np.sin(2*np.pi*5*t) + 0.5*np.sin(2*np.pi*50*t)   # 5Hz real signal + 50Hz noise

b, a = butter(N=4, Wn=15, fs=fs, btype='low')    # design a 4th-order filter, cutoff at 15Hz
filtered = filtfilt(b, a, signal)                    # apply it

import matplotlib.pyplot as plt
plt.plot(t, signal, alpha=0.4, label="raw (noisy)")
plt.plot(t, filtered, linewidth=2, label="filtered")
plt.legend()
plt.xlabel("Time (s)")
plt.show()
What butter() actually returns, and why filtfilt (not just filter)

butter designs a filter and returns two coefficient arrays (b, a) that mathematically describe the filter — you're not writing the filtering math yourself, just specifying what you want (order, cutoff frequency, low/high/bandpass) and SciPy computes the coefficients. filtfilt applies those coefficients forward and then backward through the signal, which cancels out the phase delay a single forward pass would introduce — critical when you need the filtered signal to stay precisely time-aligned with other sensor data (Sensor Fusion, later in your roadmap), rather than being shifted slightly in time relative to the original.

Worked problem — smoothing noisy IMU data 
import numpy as np
from scipy.signal import butter, filtfilt

fs = 100    # a typical low-cost IMU sample rate
t = np.arange(0, 5, 1/fs)
true_motion = np.sin(2*np.pi*0.5*t)                       # a slow, real 0.5Hz motion
noise = np.random.randn(len(t)) * 0.3                        # sensor noise
raw_accel = true_motion + noise

b, a = butter(N=3, Wn=2, fs=fs, btype='low')                  # cutoff well above 0.5Hz,
                                                                  # well below noise frequencies
smoothed = filtfilt(b, a, raw_accel)

error_before = np.abs(raw_accel - true_motion).mean()
error_after = np.abs(smoothed - true_motion).mean()
print(f"Average error before filtering: {error_before:.3f}")
print(f"Average error after filtering:  {error_after:.3f}")

Choosing the cutoff frequency (2Hz here) is a real engineering judgment call: it needs to sit comfortably above the real signal's frequency (0.5Hz) so the true motion passes through unaffected, but well below the noise's dominant frequencies so the noise gets attenuated — too close to the signal risks distorting it, too close to the noise risks not removing enough of it.

Section 8.3

Interpolation — filling in the gaps between measurements

import numpy as np
from scipy.interpolate import interp1d

known_times = np.array([0, 1, 2, 3, 4])
known_speeds = np.array([0, 45, 78, 95, 92])

f = interp1d(known_times, known_speeds, kind='linear')   # or 'cubic' for a smoother curve

new_times = np.linspace(0, 4, 50)      # 50 points, densely filling the same range
smooth_speeds = f(new_times)             # estimate the speed at EVERY one of those 50 points
How this differs from Pandas' merge_asof, and when to use which

Chapter 7's merge_asof finds the nearest existing value — it never invents a value that wasn't actually measured. interp1d genuinely estimates a value at a point that was never measured, by fitting a line (or curve) between the known points around it. Use interpolation when you need an actual estimate at an arbitrary point (resampling a signal onto a common time grid, exactly the "compare two laps by distance" problem's true underlying need); use merge_asof when the nearest real measurement is good enough and you'd rather not invent data that wasn't collected.

'linear' vs. 'cubic' — the practical difference

kind='linear' connects known points with straight lines (fast, always reasonable, but visibly "kinked" at each known point). kind='cubic' fits a smooth curve through the points (better matches physically continuous phenomena like speed or temperature, which don't actually change instantaneously) but can occasionally overshoot between points if the data is noisy — a real tradeoff worth being aware of, not just picking the fancier-sounding option by default.

Section 8.4

scipy.optimize — curve fitting

import numpy as np
from scipy.optimize import curve_fit

def model(x, a, b):          # the SHAPE of relationship we believe the data follows
    return a * x + b            # here, a straight line -- but could be any function

x_data = np.array([1, 2, 3, 4, 5])
y_data = np.array([2.1, 3.9, 6.2, 7.8, 10.1])    # roughly y = 2x, with some noise

params, _ = curve_fit(model, x_data, y_data)
a_fit, b_fit = params
print(f"Best fit: y = {a_fit:.2f}x + {b_fit:.2f}")
What curve_fit is actually doing

curve_fit searches for the parameter values (a, b here) that make model(x_data, a, b) come as close as possible to the actual y_data, in a least-squares sense — minimizing the total squared difference between predicted and actual values. This is a genuinely different tool from Chapter 5's np.linalg.solve: solve finds an exact solution to a system that has one (Linear Algebra Ch.3); curve_fit finds the best approximate fit when there's noise and no exact solution exists — precisely the situation with real sensor calibration data, where you have a model you believe is roughly correct and noisy measurements that never exactly match it.

Worked problem — calibrating a sensor

Problem: A pressure sensor outputs a raw voltage that should relate to real pressure via pressure = a*voltage + b, but the exact calibration constants are unknown. Given some voltage/pressure pairs from known reference pressures, find the calibration.

import numpy as np
from scipy.optimize import curve_fit

def calibration_model(voltage, a, b):
    return a * voltage + b

voltages = np.array([0.5, 1.2, 2.1, 3.0, 3.8])
known_pressures = np.array([101.5, 250.2, 440.8, 610.3, 780.1])   # from a reference gauge

params, _ = curve_fit(calibration_model, voltages, known_pressures)
a, b = params
print(f"Calibration: pressure = {a:.2f} * voltage + {b:.2f}")

# Now this sensor can convert any future raw voltage reading into a real pressure value
new_voltage = 2.5
estimated_pressure = calibration_model(new_voltage, a, b)
print(f"Estimated pressure at {new_voltage}V: {estimated_pressure:.1f}")

This exact pattern — collect known reference points, fit a model, use the fitted model to convert future raw readings — is precisely how real sensor calibration is done in practice, and it directly generalizes: swap in a different model function (quadratic, logarithmic, whatever physically matches the sensor's real behavior) and curve_fit handles the rest identically.

Wrap-up

Recap

  1. SciPy builds on NumPy, organized into domain-specific submodules — signal (filtering), interpolate, optimize (curve fitting), integrate, and fft.
  2. scipy.signal.butter + filtfilt implement the Signals & Systems filtering concepts as real, runnable code — filtfilt's forward-backward pass avoids the phase delay a single-direction filter would introduce.
  3. Interpolation estimates values at points that were never actually measured (unlike merge_asof's nearest-real-value approach) — appropriate when you genuinely need a value at an arbitrary point, not just the closest available measurement.
  4. curve_fit finds the best-fit parameters for a model function against noisy data — a different tool from exact linear system solving (Linear Algebra Ch.3), suited to situations where no exact solution exists.
  5. Sensor calibration — collecting known reference points, fitting a model, then applying that model to future raw readings — is a direct, practical application of curve_fit you'll use throughout your CPS hardware work.
Check yourself

Quick check

Question 1

Why does filtfilt apply a filter forward AND backward through a signal, rather than just once?

A single forward pass introduces a phase delay -- shifting the filtered signal slightly in time relative to the original. Applying the filter a second time in reverse cancels out that delay, keeping the filtered signal precisely time-aligned with the original, which matters when comparing it against other sensor data.
Question 2

What's the key difference between using interp1d and using Pandas' merge_asof to combine two datasets along a shared axis?

merge_asof finds the nearest EXISTING measured value -- it never invents data. interp1d genuinely estimates a value at a point that was never measured, by fitting a line or curve between the surrounding known points.
Question 3

Why is curve_fit the right tool for sensor calibration, rather than np.linalg.solve?

np.linalg.solve finds an exact solution to a system of equations that has one. Real sensor calibration data is noisy and rarely fits a model exactly, so curve_fit instead finds the best APPROXIMATE fit by minimizing the total difference between the model's predictions and the actual noisy measurements.

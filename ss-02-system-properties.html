System Properties

Chapter 1 described signals. This chapter describes what acts on them. A system takes an input signal and produces an output signal, and almost everything useful you can say about a system comes down to a short checklist of yes/no properties: is it linear, is it time-invariant, does it have memory, is it causal, is it stable, is it invertible. This chapter defines each one precisely, gives a mechanical test for it, and — most importantly — explains why the combination linear + time-invariant is the special case the rest of the topic (and most of control theory) is built on.

Section 2.1

What a system is

A system is anything that transforms an input signal into an output signal. We write it as an operator:

y(t) = T{ x(t) }        (continuous time)
y[n] = T{ x[n] }        (discrete time)

T is the rule. The system is the rule itself, not any single input-output pair: one system responds to infinitely many different inputs.

A system is a rule that maps an input signal to an output signal.

Examples worth having in your head for the rest of the chapter:

SystemRuleWhere it appears
Gainy(t) = 3x(t)An amplifier
Squarery[n] = x²[n]Computing signal power sample by sample
Moving averagey[n] = ⅓ (x[n] + x[n−1] + x[n−2])Smoothing a noisy ADC reading in firmware
Accumulatory[n] = Σ x[k] (k ≤ n)The integral term of a PID controller
Differentiatory(t) = dx/dtThe D term of a PID controller
Modulatory(t) = x(t) cos(2πfct)Radio transmission
Downsamplery[n] = x[2n]Reducing a sensor's data rate
Connection to what you already know

In Control Systems Ch. 1 the "plant" was a box between an input and an output. This chapter names precisely which kinds of box you can analyze with a transfer function: exactly the LTI ones. When Control Systems Ch. 2 said "assume the system is LTI", these are the properties it was assuming.

A property is a claim about all inputs

Checking that a system behaves linearly for x = 1 and x = 2 proves nothing. Each property below says "for every allowed input". To show a property holds you need a general argument; to show it fails, one counterexample is enough. Keep that asymmetry in mind throughout — it decides how each test is structured.

Section 2.2

Linearity

A system is linear if it obeys superposition. Precisely, for any two inputs x₁, x₂ and any constants a, b:

T{ a·x₁ + b·x₂ }  =  a·T{x₁} + b·T{x₂}

This packs two rules into one: additivity (the response to a sum is the sum of the responses) and homogeneity (scaling the input scales the output by the same factor).

The test

Pick two arbitrary inputs x₁ and x₂ and constants a and b. Compute the left side by feeding the combination a·x₁ + b·x₂ through the rule. Compute the right side by feeding each input through separately and combining the outputs. If they agree for all choices, the system is linear; if you find any choice where they differ, it is not.

Worked tests 
y[n] = 3x[n]                    (gain)
  T{a x₁ + b x₂} = 3(a x₁ + b x₂) = a(3x₁) + b(3x₂)     LINEAR

y[n] = x²[n]                    (squarer)
  Take x₁ = x₂ = 1, a = b = 1:
  T{x₁ + x₂} = T{2} = 4,  but  T{x₁} + T{x₂} = 1 + 1 = 2   NOT LINEAR

y[n] = 2x[n] + 1                (affine)
  T{2·x} with x = 1:  2(2·1)+1 = 5
  2·T{1}:             2(2·1+1) = 6                          NOT LINEAR

y[n] = (x[n] + x[n−1] + x[n−2]) / 3     (moving average)
  Sum of linear operations, so superposition holds          LINEAR

y(t) = dx/dt   and   y(t) = ∫ x dτ                          both LINEAR
  (derivative and integral of a sum are the sum of the derivatives / integrals)
y = 2x + 1 draws a straight line, yet it is not linear

"Linear" in signals and systems means superposition, which is stricter than "graphs as a straight line". The constant +1 breaks homogeneity. A useful necessary check: a linear system must map the zero input to the zero output (take a = 0). y = 2x + 1 gives 1 for zero input, so it fails immediately. But this is only necessary, not sufficient: y = x² gives zero for zero input and is still nonlinear, so you still have to run the full test when the quick check passes. A system like y = 2x + 1 is called affine or incrementally linear: its change in output is a linear function of the change in input.

Why linearity is worth so much

If a system is linear, you can break any complicated input into simple pieces, find the response to each piece, and add. That single idea powers everything from Fourier analysis (pieces = sinusoids) to convolution (pieces = impulses). It is also the same "linear" as Linear Algebra: a matrix multiplication y = Ax satisfies A(ax₁ + bx₂) = aAx₁ + bAx₂. Every linear system is, in a sense, a (possibly infinite) matrix acting on a signal viewed as a vector.

Section 2.3

Time-invariance

A system is time-invariant if its behavior does not change with time. Delay the input by any amount, and the output is the same output, delayed by the same amount:

if  x(t) → y(t)   then   x(t − t₀) → y(t − t₀)     for every t₀
if  x[n] → y[n]   then   x[n − k]  → y[n − k]      for every integer k

Intuition: a time-invariant system has no clock. It cannot tell whether the input arrived at 9:00 or at 9:05; it responds to the shape of the input, not to when it happens.

The test — two paths that must agree

Path 1:  delay the INPUT first, then apply the system:    T{ x(t − t₀) }
Path 2:  apply the system first, then delay the OUTPUT:   y(t − t₀)

Time-invariant  ⇔  Path 1 equals Path 2 for every x and t₀.
Worked tests 
y[n] = x²[n]
  Path 1: T{x[n−k]} = x²[n−k]
  Path 2: y[n−k]    = x²[n−k]                       TIME-INVARIANT

y(t) = t · x(t)
  Path 1: T{x(t−t₀)} = t · x(t−t₀)
  Path 2: y(t−t₀)    = (t−t₀) · x(t−t₀)
  Different (the factor t vs. t−t₀)                TIME-VARYING

y(t) = x(2t)              (time compression)
  Path 1: T{x(t−t₀)} evaluates x₁(2t) with x₁(t)=x(t−t₀)  →  x(2t − t₀)
  Path 2: y(t−t₀) = x(2(t−t₀)) = x(2t − 2t₀)
  Different                                         TIME-VARYING

y[n] = x[−n]              (reflection)
  Path 1: T{x[n−k]} = x[−n−k]
  Path 2: y[n−k]    = x[−(n−k)] = x[−n+k]
  Different                                         TIME-VARYING

y[n] = (x[n] + x[n−1] + x[n−2]) / 3    (moving average)
  Delaying the input just delays every term equally  TIME-INVARIANT
The most common error: shifting the wrong thing in Path 1

In Path 1 the delay is applied to the input signal before the rule acts, so it is the rule that then substitutes its own argument. For y(t) = x(2t), it is easy to shift the output's argument by t₀ and conclude "it's fine". The correct Path 1 is: define the shifted input x₁(t) = x(t − t₀), then apply the rule to x₁, i.e. y₁(t) = x₁(2t) = x(2t − t₀). Whenever the rule rescales, reflects, or multiplies by an explicit t, expect time-variance.

LTI: the combination that matters

Why "linear and time-invariant" is a special club

A linear time-invariant (LTI) system is completely determined by its response to a single impulse — Chapter 3 proves this and derives the convolution formula. Combined with the eigenfunction property of ejωt from Chapter 1, LTI systems are also completely described by how they scale each frequency: their frequency response. Control Systems Ch. 2's transfer function G(s) exists precisely because the motor and RC-circuit models were LTI. If a system is not LTI, none of that machinery applies directly — you would linearize it around an operating point first, which is why control engineers do that so routinely.

Section 2.4

Memory and causality

Memory

A system is memoryless if its output at any instant depends only on the input at that same instant. Otherwise it has memory.

  • y(t) = 3x(t), y[n] = x²[n], and y(t) = x(t) cos(2πt) are memoryless.
  • y[n] = x[n − 1] (a one-sample delay), the moving average, and the accumulator all have memory: they need values of the input from other times. In firmware, memory is literally variables that persist between loop iterations.

Causality

A system is causal if its output at time t depends only on the input at times ≤ t: present and past, never future.

SystemCausal?Why
y[n] = x[n] + x[n−1]Yesuses present and one past sample
y[n] = x[n+1]Noneeds the next sample
y(t) = x(t + 1)Nooutput at t needs input one second ahead
y(t) = x(−t)Noat t = −1 it needs x(+1), a future value
y[n] = ⅓(x[n−1] + x[n] + x[n+1])Nothe "centered" moving average peeks at x[n+1]
y[n] = x²[n]Yesmemoryless systems are always causal
Memoryless implies causal — but not the other way around

If output depends only on the present input, it certainly does not depend on the future. But a causal system can have memory (the accumulator is causal and has memory). Also watch for hidden non-causality behind an innocent-looking substitution such as x(−t) or x(2t): x(2t) at t = 1 uses x(2), which is in the future of t = 1. Test by picking a specific time and asking "what input times does this output need?"

Real-time firmware must be causal — offline processing need not be

Code running in a control loop cannot read a sensor value that has not been measured yet, so every real-time system is causal. But if you are filtering a recorded audio file or a saved dataset, all samples are already available, and a non-causal (centered) filter is perfectly implementable — it often performs better because it does not lag the data. A causal version of the centered average is y[n] = ⅓(x[n] + x[n−1] + x[n−2]): same smoothing, but delayed by one sample. That delay is the price of causality, and it matters in a feedback loop (Control Systems Ch. 7: delay erodes stability margin).

Section 2.5

BIBO stability

A system is BIBO stable (bounded-input, bounded-output) if every bounded input produces a bounded output. Formally: if there is a constant Bx such that |x| ≤ Bx for all time, then there must exist some finite By such that |y| ≤ By for all time.

The plain-language reading: a well-behaved input can never make the output run away to infinity. A robot arm that responds to a bounded voltage command by accelerating without limit is unstable in exactly this sense.

How to prove stability — and how to disprove it

  • To prove stable: assume |x| ≤ Bx and show the output is bounded by some constant that you can name. This requires a general argument for all such inputs.
  • To prove unstable: exhibit one bounded input whose output is unbounded. One counterexample suffices.
Worked tests 
y[n] = 3x[n]
  |y| = 3|x| ≤ 3·B_x                                        STABLE

y[n] = (x[n] + x[n−1] + x[n−2]) / 3
  |y| ≤ (B_x + B_x + B_x)/3 = B_x                           STABLE

y(t) = e^{x(t)}
  |x| ≤ B_x  →  y ≤ e^{B_x}                                 STABLE
  (a nonlinear system can still be BIBO stable)

y[n] = Σ x[k]   (k from −∞ to n)     (accumulator)
  Counterexample: x[n] = u[n]  (bounded by 1)
  y[n] = n + 1 for n ≥ 0 — grows without bound              UNSTABLE

y(t) = ∫ x(τ)dτ (from −∞ to t)        (integrator)
  Counterexample: x(t) = u(t)  → y(t) = t·u(t), a ramp      UNSTABLE

y(t) = t · x(t)
  Counterexample: x(t) = 1  → y(t) = t, unbounded           UNSTABLE
A bounded input (a step) fed to an accumulator produces an unbounded output: the accumulator is BIBO unstable.
"Stable" here is about input-output behavior, not about the system "seeming calm"

A system that just oscillates forever at a fixed amplitude (an ideal undamped oscillator, or a perfect integrator sitting still) looks bounded when there is no input — but it is BIBO unstable, because a suitably chosen bounded input (one that matches its natural frequency, or a constant fed into an integrator) drives the output to infinity. This matches Control Systems Ch. 5: poles exactly on the imaginary axis are "marginally stable", which is not good enough for BIBO stability.

The bridge to Control Systems Ch. 5

For an LTI system with a rational transfer function, BIBO stability is equivalent to all poles lying strictly in the left half of the s-plane (for discrete-time systems: strictly inside the unit circle). That is exactly the criterion the Routh-Hurwitz test checked. The accumulator has a pole at s = 0 (in discrete time, at z = 1) — on the boundary, and so it fails. A recursive system y[n] = a·y[n−1] + x[n] is BIBO stable exactly when |a| < 1, the same "aⁿ decays" fact from Chapter 1.

Section 2.6

Invertibility

A system is invertible if distinct inputs always produce distinct outputs — so that, in principle, you can recover the input from the output. If it is invertible, an inverse system exists which, cascaded after the original, returns the input exactly.

SystemInvertible?Reason / inverse
y(t) = 2x(t)Yesinverse: x(t) = y(t)/2
y[n] = x²[n]Nox and −x give the same output; the sign is lost
y[n] = Σ x[k] (accumulator)Yesinverse: x[n] = y[n] − y[n−1] (the first difference)
y[n] = x[n] − x[n−1] (first difference)Noany constant input gives zero output; the DC level is lost
y(t) = dx/dtNox(t) and x(t) + 5 have the same derivative
y[n] = x[2n] (downsampler)Nodiscards every odd-indexed sample
Same idea as a matrix inverse

In Linear Algebra Ch. 4, a matrix is invertible exactly when it does not collapse different vectors onto the same output (nonzero determinant). Here it is the same requirement for a system. The differentiator has the signal-processing equivalent of a singular matrix: it sends a whole family (all constants) to zero.

The inverse of a stable system can be unstable

Take the stable system y[n] = x[n] + 2x[n−1] (|y| ≤ 3·Bx). Its causal inverse is x[n] = y[n] − 2x[n−1], a recursion with coefficient −2, and |−2| > 1, so by the rule from Section 2.5 that inverse is unstable. In practice this matters for equalization and deconvolution: undoing a sensor's or channel's distortion means applying its inverse system, and if that inverse is unstable or amplifies noise, the "correction" makes things worse. Whether a system can be safely inverted is a real design question, not a formality.

Section 2.7

Worked problem — classify four systems

Problem

Classify each of the following systems for linearity, time-invariance, memory, causality, BIBO stability, and invertibility.

S1: y[n] = x[n] − x[n−1]    S2: y(t) = x(t) cos(2πt)    S3: y[n] = x[2n]    S4: y[n] = x²[n]

LinearTime-invariantMemorylessCausalBIBO stableInvertible
S1YesYesNoYesYesNo
S2YesNoYesYesYesNo
S3YesNoNoNoYesNo
S4NoYesYesYesYesNo

Reasoning for the non-obvious cells:

S1  Linear/TI: a difference of shifted copies of x is a linear combination
    of shifts, so both hold. Stable: |y| ≤ |x[n]| + |x[n−1]| ≤ 2·B_x.
    Not invertible: a constant input c gives output 0 for every c.

S2  Not TI: shifting the input gives x(t−t₀)cos(2πt), but shifting the
    output gives x(t−t₀)cos(2π(t−t₀)). These differ unless t₀ is a whole
    number of seconds. The explicit cos(2πt) is a built-in clock.
    Stable: |y| ≤ |x| because |cos| ≤ 1.
    Not invertible: wherever cos(2πt) = 0, the input is erased.

S3  Linear: T{a x₁ + b x₂}[n] = a x₁[2n] + b x₂[2n].
    Not TI: shift input by 1 → y₁[n] = x[2n−1]; shift output by 1 →
    y[n−1] = x[2n−2]. Different.
    Not causal: y[1] = x[2], which is in the future of index 1.
    Has memory: output at n uses input at index 2n ≠ n.
    Not invertible: odd-indexed samples are discarded.

S4  Not linear (Section 2.2's counterexample). TI, memoryless, causal,
    stable (|y| ≤ B_x²). Not invertible: the sign is lost.

What to take away: only S1 is LTI. S2 is linear but time-varying (a common surprise for modulators), S3 is linear but time-varying because it changes the time scale, and S4 is time-invariant but nonlinear. "Looks simple" is not the same as "LTI"; the tests, not the appearance, decide.

Wrap-up

Recap

  1. A system is a rule T that maps an input signal to an output signal. Every property is a claim about all inputs: one counterexample disproves it, a general argument is needed to prove it.
  2. Linear means superposition: T{a·x₁ + b·x₂} = a·T{x₁} + b·T{x₂}. Zero-in-zero-out is necessary but not sufficient (y = x² passes it and is still nonlinear). Linear systems are the same idea as matrices acting on vectors.
  3. Time-invariant means delaying the input just delays the output. Test: compare T{x(t − t₀)} to y(t − t₀). Rescaling, reflecting, or multiplying by an explicit t all make a system time-varying.
  4. Memoryless: output depends only on the present input. Causal: output depends only on present and past inputs; real-time firmware must be causal, offline processing need not be. Memoryless implies causal; the reverse is false.
  5. BIBO stable: every bounded input gives a bounded output. Prove it in general; disprove it with one bounded input that gives an unbounded output (a step into an accumulator). For LTI systems it means all poles strictly in the left half-plane (or inside the unit circle).
  6. Invertible: distinct inputs give distinct outputs. Differentiators, squarers, and downsamplers lose information and are not invertible; an accumulator is invertible, with the first difference as its inverse.
  7. The special class LTI (linear + time-invariant) is fully described by its impulse response (Chapter 3) and its frequency response (Chapters 4–5), and is exactly what a transfer function describes.
Check yourself

Quick check

Question 1

The system y[n] = 5x[n] + 2 draws a straight line. Is it linear? Give the fastest check.

No. A linear system must give zero output for zero input (take a = 0 in the superposition rule). Here x = 0 gives y = 2, so it fails immediately. It is an affine system: its change in output is linear in the change in input, but it is not linear in the superposition sense.
Question 2

Is y(t) = x(3t) time-invariant? Show the two paths.

No. Path 1 (delay the input, then apply the rule): the shifted input is x(t − t₀), so the output is x(3t − t₀). Path 2 (apply the rule, then delay the output): y(t − t₀) = x(3(t − t₀)) = x(3t − 3t₀). These differ unless t₀ = 0, so the system is time-varying.
Question 3

Is the centered moving average y[n] = ⅓(x[n−1] + x[n] + x[n+1]) causal? How can you make a causal version, and what does it cost?

It is not causal, because it uses x[n+1], a future sample. The causal version y[n] = ⅓(x[n] + x[n−1] + x[n−2]) uses only present and past samples, at the cost of delaying the smoothed output by one sample relative to the centered version. That extra delay reduces stability margin if the filter sits inside a feedback loop.
Question 4

Prove the accumulator y[n] = Σ x[k] (k ≤ n) is not BIBO stable.

Give one bounded input with an unbounded output. Let x[n] = u[n], which never exceeds 1. Then y[n] = n + 1 for n ≥ 0, which grows without bound. A single counterexample is enough to disprove BIBO stability.
Question 5

Why is the accumulator invertible but the differentiator y(t) = dx/dt not?

The accumulator's inverse is the first difference, x[n] = y[n] − y[n−1], which recovers the input exactly. The differentiator sends every constant to zero, so x(t) and x(t) + 5 produce the same output and the original cannot be recovered without extra information (the constant is lost).

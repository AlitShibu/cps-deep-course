Convolution

Chapter 2 ended with a promise: a linear time-invariant system is completely determined by its response to a single impulse. This chapter cashes that in. You will derive the convolution sum from the two ideas you already have — every signal is a sum of shifted impulses (Chapter 1), and LTI systems obey superposition and time-invariance (Chapter 2) — learn to compute it by hand in both discrete and continuous time, see what its algebraic properties say about cascaded and parallel systems, and then watch it become the most common loop in embedded signal-processing code: the FIR filter.

Section 3.1

Where convolution comes from: the impulse response

Feed the impulse δ[n] into an LTI system and record what comes out. That output is called the system's impulse response, written h[n] (or h(t) in continuous time):

h[n] = T{ δ[n] }

It is a complete fingerprint of the system. Here is the whole argument, using only results you already have:

Step 1 (Ch. 1)  Any input is a sum of shifted, weighted impulses:
                    x[n] = Σ x[k] · δ[n − k]

Step 2 (Ch. 2, time-invariance)  Delaying the input delays the output:
                    T{ δ[n − k] } = h[n − k]

Step 3 (Ch. 2, linearity)  The response to a weighted sum is the
                    weighted sum of the responses:

                    y[n] = T{ Σ x[k] δ[n − k] } = Σ x[k] · h[n − k]

The result is the convolution sum:

y[n] = Σ x[k] · h[n − k]   (sum over all integers k)
     = (x * h)[n]

In continuous time the sum becomes an integral:

y(t) = ∫ x(τ) · h(t − τ) dτ   (τ from −∞ to ∞)
     = (x * h)(t)
Reading the formula in plain words

Each input sample x[k] fires off its own copy of the impulse response, scaled by x[k] and starting at time k. The output at any moment is the sum of all those overlapping, scaled, delayed echoes. Convolution is nothing more than "add up the echoes".

Impulse responses of systems you already know

SystemImpulse response
Gain, y = 3xh[n] = 3δ[n]
One-sample delay, y[n] = x[n−1]h[n] = δ[n − 1]
Moving average of 3 samplesh[n] = ⅓ for n = 0, 1, 2; zero elsewhere
Accumulatorh[n] = u[n] (feed δ in, the running sum is 1 forever after)
Recursive y[n] = 0.5·y[n−1] + x[n]h[n] = (0.5)ⁿ u[n]
RC low-pass (Basic Electronics Ch. 3)h(t) = (1/RC) e−t/RC u(t)
This is the same thing as the transfer function — seen from the time domain

In Control Systems Ch. 2 you described a system by its transfer function G(s). The Laplace transform of the impulse response h(t) is G(s). Multiplying by G(s) in the s-domain and convolving with h(t) in the time domain are the same operation. The transform simply turns the awkward integral into an ordinary product, which is exactly why Chapter 5 will do the same for the Fourier transform.

This only works for LTI systems

Step 2 needs time-invariance and step 3 needs linearity. For a time-varying system (like the modulator from Chapter 2) or a nonlinear one (the squarer), a single impulse response does not describe the whole system, and the convolution formula gives wrong answers. Always confirm LTI first.

Section 3.2

Computing discrete-time convolution

Take the formula y[n] = Σ x[k]·h[n − k] and read it as a recipe for one output value. To get a particular y[n]: (1) flip h around to get h[−k]; (2) slide it so it is shifted by n, giving h[n − k]; (3) multiply it point-by-point with x[k]; (4) add up the products. Repeat for each n. This is the flip-and-slide picture.

A worked example

Let x[n] = {1, 2, 3} for n = 0, 1, 2, and h[n] = {1, 1} for n = 0, 1. Then:

y[0] = x[0]h[0]                       = 1·1         = 1
y[1] = x[0]h[1] + x[1]h[0]            = 1 + 2       = 3
y[2] = x[1]h[1] + x[2]h[0]            = 2 + 3       = 5
y[3] = x[2]h[1]                       = 3           = 3

y[n] = {1, 3, 5, 3}   for n = 0..3
x convolved with h. The output is longer than either input, and its total area equals the product of the input areas (6 × 2 = 12).

Three sanity checks worth running every time

  • Length. If x has L₁ non-zero samples and h has L₂, then y has L₁ + L₂ − 1. Here 3 + 2 − 1 = 4. ✓
  • Sum of samples. Σy = (Σx)·(Σh). Here 6 × 2 = 12 and 1 + 3 + 5 + 3 = 12. ✓
  • Start index. y starts at the sum of the two start indices, and ends at the sum of the two end indices.

The table (grid) method — faster and less error-prone

Because y[n] pairs x[k] with h[n − k], the two indices always add up to n. So write x down the side, h across the top, fill in every product, and add along the anti-diagonals, where index sum is constant.

Example: x = {1, 2, 3}, h = {1, 0, −1}.

x[k] \ h[m]h[0] = 1h[1] = 0h[2] = −1
x[0] = 110−1
x[1] = 220−2
x[2] = 330−3
Index sum 0:  1                      → y[0] =  1
Index sum 1:  0 + 2                  → y[1] =  2
Index sum 2:  −1 + 0 + 3             → y[2] =  2
Index sum 3:  −2 + 0                 → y[3] = −2
Index sum 4:  −3                     → y[4] = −3

y[n] = {1, 2, 2, −2, −3}     Check: Σy = 0 = (Σx)(Σh) = 6 × 0 ✓
You have already done this before

This is exactly how you multiply polynomials. (1 + 2z + 3z²)·(1 + 0z − z²) gives the same coefficients: 1 + 2z + 2z² − 2z³ − 3z⁴. Convolution of sequences is polynomial multiplication of their generating polynomials — a fact that resurfaces when you meet the z-transform.

Three classic slips

(1) Forgetting to flip. Sliding h without reversing it computes correlation, not convolution — the results differ unless h is symmetric. (2) Losing track of index ranges — the grid method fixes this. (3) Mixing up k and n. k is the dummy variable that gets summed away; n is the output index you are computing. Only n survives in the answer.

Section 3.3

Continuous-time convolution

The continuous-time integral y(t) = ∫ x(τ) h(t − τ) dτ is evaluated with the same flip-and-slide idea, except that the "sum of products" becomes the area under the product. The variable of integration is τ; t is the output time and behaves like a constant during each integration.

Example 1 — the step response of an RC circuit

Let x(t) = u(t) (a step) and h(t) = e−t u(t) (an RC low-pass with RC = 1 s). Then:

y(t) = ∫ u(τ) · e^{−(t−τ)} u(t − τ) dτ

u(τ) = 1 only for τ > 0;  u(t − τ) = 1 only for τ < t.
So for t < 0 the two never overlap: y(t) = 0.
For t ≥ 0, integrate only over 0 < τ < t:

y(t) = ∫ e^{−(t−τ)} dτ   (τ from 0 to t)
     = [ e^{−(t−τ)} ]  from τ = 0 to τ = t
     = 1 − e^{−t}          for t ≥ 0

That is precisely the charging curve you know from Basic Electronics and the first-order step response from Control Systems Ch. 3: it starts at 0, rises with time constant 1 s, and settles at 1. Convolution reproduced it from the impulse response alone.

Example 2 — two rectangular pulses give a triangle

Let x(t) = h(t) = 1 for 0 ≤ t ≤ 1 and 0 otherwise. As h(t − τ) slides across x(τ), the overlap grows linearly from 0 to 1, then shrinks back to 0:

y(t) = 0            for t < 0
y(t) = t            for 0 ≤ t ≤ 1     (overlap length grows)
y(t) = 2 − t        for 1 ≤ t ≤ 2     (overlap length shrinks)
y(t) = 0            for t > 2
Convolving two unit pulses: the result is a triangle of width 2 and peak 1. Widths add (1 + 1 = 2), and the peak equals the maximum overlap.
A recipe that works for any CT convolution

(1) Sketch x(τ) and the flipped h(−τ). (2) Slide h(t − τ) from t = −∞ rightward. (3) Note the values of t where the overlap pattern changes — those are the breakpoints, and each range between breakpoints gets its own integral. (4) In each range, integrate the product over the overlap region only, with correct limits. (5) Sanity-check the endpoints: the output is zero before the signals first touch and after they finally separate.

Smoothing is a general effect

Convolving two rectangles produced a triangle: the result is smoother and wider than either input. Convolution generally blurs and spreads signals, adding their durations. That is why a low-pass filter smooths a noisy sensor reading and why a slow sensor "smears" a sharp event across time. Repeat the process enough times (triangle with a rectangle, and so on) and the shape approaches a bell curve — the same effect that the Central Limit Theorem describes.

Section 3.4

Properties, and what h tells you about a system

Algebraic properties

PropertyStatementWhat it means for systems
Commutativex * h = h * xYou may swap which signal is the "input" and which is the "system" when computing
Associative(x * h₁) * h₂ = x * (h₁ * h₂)Two systems in cascade act like one with h = h₁ * h₂ — and their order does not matter
Distributivex * (h₁ + h₂) = x*h₁ + x*h₂Two systems in parallel act like one with h = h₁ + h₂
Identityx * δ = xThe impulse is the "do nothing" system
Shiftx[n] * δ[n − k] = x[n − k]Convolving with a shifted impulse delays the signal
Shift invariance of the resultif y = x * h, then x(t − t₀) * h = y(t − t₀)Time-invariance, restated
Cascade and parallel — the block diagram algebra you already met

In Control Systems Ch. 4 you reduced block diagrams by multiplying transfer functions in series and adding them in parallel. Here is the time-domain version of exactly that: convolve impulse responses in series, add them in parallel. Same rules, different domain.

Reading system properties from h

Because h describes an LTI system completely, every property from Chapter 2 becomes a simple condition on h:

PropertyCondition on h
Memorylessh[n] = K·δ[n] (a pure gain)
Causalh[n] = 0 for all n < 0 (the output cannot start before the impulse arrives)
BIBO stableΣ |h[n]| < ∞ (CT: ∫ |h(t)| dt < ∞) — h must be absolutely summable
Why the stability condition is exactly Σ|h| < ∞ 
Sufficient: if |x[n]| ≤ B_x for all n, then
  |y[n]| = |Σ h[k] x[n−k]| ≤ Σ |h[k]| |x[n−k]| ≤ B_x · Σ |h[k]|
  which is finite whenever Σ|h| is finite.

Necessary: if Σ|h| = ∞, choose the bounded input x[n] = sign(h[−n]).
  Then y[0] = Σ h[k]·sign(h[k]) = Σ |h[k]| = ∞ — unbounded output.

Applying it: h[n] = (0.5)ⁿ u[n] has Σ|h| = 1/(1 − 0.5) = 2, finite, so it is stable. The accumulator h[n] = u[n] has Σ|h| = ∞, so it is unstable — the same verdict Chapter 2 reached by counterexample, now obtained without hunting for one.

Finite vs. infinite impulse response

A system whose h[n] is non-zero for only finitely many samples is called an FIR (finite impulse response) system. The moving average is FIR. A system like y[n] = 0.5y[n−1] + x[n] has an h that never quite reaches zero — an IIR system. Every FIR system is automatically BIBO stable (a finite sum of finite numbers), which is one reason FIR filters are so popular in firmware. An IIR filter needs its stability checked, which is where the pole-location rules from Control Systems Ch. 5 come back.

Section 3.5

Convolution in firmware: the FIR filter

A causal FIR filter with N coefficients h[0], …, h[N−1] has output y[n] = Σ h[k]·x[n − k] for k = 0 to N−1. Each new output needs the current sample and the previous N−1 samples, multiplied by the filter coefficients and summed. That is convolution, computed one output at a time as new samples arrive:

#define N 3
float h[N]   = { 1.0f/3, 1.0f/3, 1.0f/3 };   // moving average of 3 samples
float buf[N] = { 0 };                        // buf[k] holds x[n-k]

float fir_step(float x_new) {
    for (int k = N - 1; k > 0; k--)          // shift history by one sample
        buf[k] = buf[k - 1];
    buf[0] = x_new;

    float y = 0;
    for (int k = 0; k < N; k++)              // y[n] = sum of h[k] * x[n-k]
        y += h[k] * buf[k];
    return y;
}

// In the sampling loop (every T_s, e.g. from a timer interrupt):
//   float y = fir_step(adc_reading);
What this code is, mathematically

The shifting loop implements the delays x[n − 1], x[n − 2], …; the multiply-accumulate loop is the convolution sum. Changing the numbers in h[] changes the filter without changing any code: {⅓, ⅓, ⅓} smooths, {1, −1} approximates a derivative, and a longer, carefully designed h[] gives a sharp low-pass or band-pass. It works only because the system is LTI — convolution with a fixed h is the whole system.

The cost of convolution

An N-tap FIR filter costs N multiplications and N − 1 additions per output sample. Convolving a whole signal of length L with an h of length N costs about L·N multiplications. On a microcontroller running at a fixed sample rate this directly limits how long a filter you can afford: at 10 kHz sampling with a 100-tap filter, you need one million multiply-accumulates per second. Many chips (Cortex-M4 and up, ESP32-S3) have hardware multiply-accumulate instructions for exactly this reason. Chapter 5 will show that the Fourier transform can turn this into a much cheaper computation for long filters.

The recursive alternative

The IIR system y[n] = 0.5·y[n−1] + x[n] has an infinitely long impulse response, but needs only one multiplication and one addition per sample. It "remembers" the entire past through the single stored value y[n−1]. In code that is a single line: y = 0.5f * y + x;. Trading a long FIR for a short recursive equation is a huge saving — with the cost that you must now check stability, as Section 3.4 explained. Low-pass "exponential smoothing" on an ADC reading, y += alpha * (x - y);, is exactly this kind of filter.

Startup transient and the initial buffer

Mathematically the convolution sum assumes the input has existed forever. On a real chip, the buffer starts at zero, so the first N − 1 outputs are computed from a partly-empty history and are not the "true" steady-state result. If your filter output must be trustworthy immediately (a safety limit, say), either ignore the first N − 1 samples or pre-load the buffer with the first real reading.

Section 3.6

Worked problem — a first-order digital filter

Problem

A digital filter has impulse response h[n] = (0.5)ⁿ u[n]. (a) Is it causal and BIBO stable? (b) Find its response to a unit step x[n] = u[n]. (c) What does the output settle at? (d) Write the equivalent one-line recursion, and say what it means for firmware.

(a) h[n] = 0 for n < 0, so it is CAUSAL.
    Σ |h[n]| = Σ (0.5)ⁿ (n from 0 to ∞) = 1/(1 − 0.5) = 2 < ∞,
    so it is BIBO STABLE.

(b) y[n] = Σ x[k] h[n − k]. For n ≥ 0 only 0 ≤ k ≤ n contribute
    (x[k] = 1 there, and h[n−k] = (0.5)^(n−k)). Substitute j = n − k:

    y[n] = Σ (0.5)^j   (j from 0 to n)
         = (1 − (0.5)^(n+1)) / (1 − 0.5)
         = 2 − (0.5)^n                        for n ≥ 0

    Spot-check:  y[0] = 2 − 1   = 1     (= x[0]h[0] = 1)         ✓
                 y[1] = 2 − 0.5 = 1.5   (= h[1] + h[0] = 0.5+1)  ✓
                 y[2] = 2 − 0.25 = 1.75 (= 0.25 + 0.5 + 1)       ✓

(c) As n → ∞, (0.5)ⁿ → 0, so y[n] → 2.
    This equals Σ h[n] — for a stable LTI system, a constant input c
    settles at c · (Σh), the "DC gain".

(d) The recursion is  y[n] = 0.5·y[n−1] + x[n].
    Check: with x = u[n], y[0] = 1, y[1] = 0.5 + 1 = 1.5,
    y[2] = 0.75 + 1 = 1.75  — matches part (b).
    In firmware: one multiply, one add, one stored variable —
    the whole infinite impulse response, computed cheaply.

What to take away: the same system was described three ways — as an impulse response (h[n]), as a convolution sum, and as a difference equation. They are interchangeable, and you should be comfortable moving between them. Also notice the step response 2 − (0.5)ⁿ has exactly the "rise toward a final value" shape of the RC circuit in Section 3.3: a discrete first-order system, with (0.5)ⁿ playing the role of e−t. This is the connection Chapter 6 will make precise when it treats sampled continuous-time systems.

Wrap-up

Recap

  1. The impulse response h is the output of an LTI system for input δ. Because every signal is a sum of shifted impulses (Ch. 1) and LTI systems obey superposition and time-invariance (Ch. 2), the output for any input is the convolution y[n] = Σ x[k]h[n − k] (CT: ∫ x(τ)h(t − τ)dτ). It applies only to LTI systems.
  2. Compute DT convolution with flip-and-slide or, more reliably, the grid method (sum along anti-diagonals). Checks: output length is L₁ + L₂ − 1, and Σy = (Σx)(Σh).
  3. CT convolution is the area of the overlap of x(τ) with the flipped, slid h(t − τ). Find the breakpoints, integrate on each range. Convolution smooths and widens signals (two unit pulses give a triangle).
  4. Convolution is commutative, associative, and distributive: cascade = convolve impulse responses, parallel = add them. Convolving with δ leaves the signal unchanged; with δ[n − k] it delays it.
  5. Properties from h: causal ⇔ h = 0 for n < 0; BIBO stable ⇔ Σ|h| < ∞; memoryless ⇔ h = Kδ. Every FIR system is stable; IIR systems need checking.
  6. In firmware, convolution with a stored h is an FIR filter (N multiplies per sample). A recursive (IIR) equation like y[n] = 0.5y[n−1] + x[n] produces an infinite impulse response with one multiply — at the cost of needing a stability check.
Check yourself

Quick check

Question 1

Compute x * h for x[n] = {2, 1} (n = 0, 1) and h[n] = {1, 3, 1} (n = 0, 1, 2). Check your answer.

y[0] = 2·1 = 2; y[1] = 2·3 + 1·1 = 7; y[2] = 2·1 + 1·3 = 5; y[3] = 1·1 = 1. So y = {2, 7, 5, 1}. Checks: length 2 + 3 − 1 = 4 ✓; Σy = 15 = (Σx)(Σh) = 3 × 5 ✓.
Question 2

Why does the convolution formula fail for the modulator y(t) = x(t)cos(2πt)?

The derivation needs time-invariance (so that the response to a shifted impulse is a shifted h) and linearity (to sum the responses). The modulator is linear but time-varying, so there is no single impulse response h(t) that describes it, and convolving with any one h would give wrong answers.
Question 3

Two LTI systems with impulse responses h₁[n] = δ[n − 1] and h₂[n] = δ[n − 2] are cascaded. What is the equivalent impulse response? What if they are placed in parallel instead?

Cascade: h = h₁ * h₂ = δ[n − 1] * δ[n − 2] = δ[n − 3], a delay of 3 samples. Parallel: h = h₁ + h₂ = δ[n − 1] + δ[n − 2], an output that adds the input delayed by 1 and by 2 samples.
Question 4

A system has h[n] = 2ⁿ u[n]. Is it causal? Is it BIBO stable?

Causal: yes, h[n] = 0 for n < 0. Stable: no. Σ |h[n]| = Σ 2ⁿ diverges, so the absolutely-summable condition fails. A bounded input such as a unit step gives an output that grows without limit.
Question 5

Why is an FIR filter always BIBO stable, while an IIR filter is not guaranteed to be?

An FIR filter has only finitely many non-zero h values, so Σ|h| is a finite sum of finite numbers and always converges. An IIR filter has an infinitely long h, and whether Σ|h| converges depends on the coefficients — for example y[n] = a·y[n−1] + x[n] is stable only when |a| < 1.
